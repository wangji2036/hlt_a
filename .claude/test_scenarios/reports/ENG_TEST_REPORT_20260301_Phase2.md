## 5. 异常记录与根因分析

### 异常 #1: TC-ENG-205/207 — WB7720 写保护时序冲突 (CRITICAL)

| 字段 | 内容 |
|------|------|
| 关联用例 | TC-ENG-205, TC-ENG-207 |
| 严重程度 | **Critical** — 阻断全部虚拟参数注入 |
| 复现率 | 必现 (100%) |
| 根因分析 | **测试脚本 enter_eng_mode() 写入顺序与 WB7720 写保护逻辑冲突** |
| 责任模块 | `phase2_test.py` enter_eng_mode() (commit `53d2bc9`) |
| 修复状态 | **待修复** — 需 revert 写入顺序 |

**根因详解**:

Commit `53d2bc9` 将 `enter_eng_mode()` 的写入顺序从「先解锁 0x50=0xA5，再写参数 0x60-0x86」改为「先写参数 0x60-0x86，再解锁 0x50=0xA5」。

但 WB7720 CMD 0x0C 处理函数 (`main.c:522-543`) 对 0x60-0x88 范围的写入有保护检查：

```c
if ((wr_addr >= REG_ENG_CURRENT_DATE && ...) || (wr_addr >= REG_ENG_VIRTUAL_CELL1 && ...)) {
    if (i2c_buff[REG_WORK_MODE] == ENGINEERING_MODE_KEY)  // 0x50 == 0xA5?
        i2c_buff[wr_addr] = Vendor_Request[3 + i];
    // else: 写入被静默丢弃！
}
```

**结果**: 当先写参数 0x60-0x86（此时 0x50 仍为 0x00），WB7720 静默丢弃所有参数写入。之后写 0x50=0xA5 虽然成功，但 i2c_buff 中参数区仍是旧值/零值。NU17112 step 14 读取的全是空数据。

**影响范围**:
- TC-ENG-205: Cycles=100 被丢弃，NU17112 读到 0，CycleCount 始终为 0
- TC-ENG-207: Cell1=4000/4500 均被丢弃，OV_cnt 累加来自 i2c_buff 中残留的旧 OV 值
- TC-ENG-207 的 erase 本身可正常执行（0xEE 在 0x50=0xA5 之后写入），但由于 i2c_buff 中残留旧 OV 记录数据，擦除后 OV_cnt 无法归零

**正确写入时序**:
```
旧（正确）: 0x50=0xA5 → 0x60/0x70/0x80-0x86 → [可选 0x88=0xAA]
新（错误）: 0x60/0x70/0x80-0x86 → 0x50=0xA5  ← 参数全被丢弃!
```

**修复方案**: Revert 到先写 0x50=0xA5 解锁，再写参数，末尾追加 0x88=0xAA 刷新以解决原始时序竞争。

| 字段 | 内容 |
|------|------|

## 7. 结论与建议

### 7.1 总体评价
**不通过** — P0 有 2 项失败 (TC-ENG-207, TC-ENG-208)，Phase 3 准入: **否**

### 7.2 关键发现
1. **Commit 53d2bc9 引入了新 Bug**: `enter_eng_mode()` 先写参数再写 0x50，与 WB7720 写保护逻辑冲突，导致所有参数被静默丢弃
2. **TC-ENG-208 是误报**: 基线漂移导致 SOC 差值 76%，固件行为正确
3. **TC-ENG-201~204, 206 的 PASS 是假象**: 这些测试无法区分「参数注入成功但低于阈值」和「参数被丢弃，使用真实值」两种情况

### 7.3 修复优先级

| 优先级 | 修复项 | 责任 | 预计影响 |
|--------|--------|------|---------|
| **P0** | Revert enter_eng_mode() 写入顺序: 0x50 先写，params 后写 | windows-app-agent | 解决 TC-ENG-205/207/208 |
| **P0** | 保留 0x88=0xAA 末尾刷新 (解决原始时序竞争) | windows-app-agent | 配合上述修复 |
| **P1** | TC-ENG-208 基线刷新稳定化 (多采样取稳定值) | windows-app-agent | 消除误报 |

### 7.4 已知限制
- `date_to_seconds()` 不支持 year < 2026, TC-ENG-210 使用 2025 年日期时 RTC 置为 epoch
- Cell1/Cell2/Temp 虚拟值仅影响 `bat_record.c` 异常检测, 遥测始终显示真实 ADC/NTC
