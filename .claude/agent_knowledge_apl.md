## 1. Architecture Overview

The APL (Application) subsystem manages the top-level application tasks for a NuVolta NU17112 powerbank SoC. It runs as `APL_TASK(4)` in the OSAL scheduling system, handling LED/GUI display, low-power sleep/wake, battery exception logging, key detection, sensor monitoring, IPGA current measurement, and I2C slave register bridge.

### Layer Diagram

```

|  config.h / debug.h                                                  |
|  Build switches, voltage thresholds, protocol enables, debug flags   |
+---------------------------------------------------------------------+
|  app.c / app.h -- APL_TASK Main Event Handler                        |
|  Timer-driven periodic tasks: 5ms/10ms/100ms/250ms                  |

| `APL_EVT_005ms_POLL` | 5ms | IPGA current measurement (4-step phase-switching: phase0 read, phase1 read, average, gain calibration). Only if `CONFIG_SUPPORT_IPGA=1` |

**IPGA Current Measurement (5ms task, `CONFIG_SUPPORT_IPGA`):**
- 4-step cycle with `get_info_step` counter (0-15, resets at >15)
- Step 0: Switch to phase 0
- Step 1: Read 10 ADC samples at 1.2V ref, average, store phase0_avg
- Step 2: Switch to phase 1
- Step 3: Read 10 ADC samples, compute `Ir = avg * 1000 * 375 / 512 / Rsns`
- Auto gain calibration: After 8 seconds idle (`pga_gain_cnt > 80`), switch to gain 20 to calculate offset
- Result stored in `gd->ipga` and `g_buckboost.adc_ibat`

**UART Communication:**
- Protocol: `0x55 '#' ... '.' 0x55` framing
- TX format: `0x55 0x55 0x23 serial_no cmd len_hex data_hex checksum '.' 0x55 0x55`
- Max buffer: 140 bytes RX, 140 bytes TX
- Checksum: Simple byte sum of payload

**Factory Q Calibration (`jig_store_Q_value_process`):**
- Trigger: ASK packet with data[0]=0x12, data[1]=0x34
- Action: Erase `AP_CFG_ROM_ADDR_BASE` flash page, write `q_fact_air` and `f_self_air`

**Wireless LED (bit 4 of `soc_show_ram_led`):**

| flash_flag | Meaning | Behavior |
|------------|---------|----------|
| 0 | Steady | All LEDs steady |
| 1 | Charging or Low SOC (<= 5%) | Highest battery LED blinks at 1Hz |
| 2 | Error | All 5 LEDs blink at 1Hz |
| 3 | Charging stat == 0 (commented out) | All LEDs off |

**Blink timing:** `flash_light_on` toggles every 2x 250ms = 500ms (1Hz blink rate via `cnt > 1`)

**SOC Update Logic (`ui_update`, line 488):**
1. On first boot (`real_soc_obtained == 0`): Wait for `SOCPack_DisplaySOC_pct > 0`, then adopt it
2. Gradual update: Every 15 seconds (`one_min_cnt > 60` at 250ms period), if charging and SOC < display, increment by 1; if discharging and SOC > display, decrement by 1
3. Clamp to 0-100
4. Optional: `SOC_1_TO_0_before_vbat_Handle` / `SOC_99_TO_100_before_vbat_Handle` for voltage-based forced SOC endpoints
5. `zero_soc_cnt` incremented when SOC <= 0 during discharge (up to 250), used for sleep entry

**SOC Handle (`soc_handle`, conditional `CONFIG_SOC_HANDLE_ENABLE`):**
- Power-based dynamic `P_AtRateCurrent_mA` adjustment
- Single battery: 4 levels (3000/5000/6500/8000 mA) based on `out_power`
- Dual battery: 8 levels (1500/2500/3250/5000/6000/7000/8000/10000 mA) with hysteresis bands

**GPIO Scan (`ui_display`, called at ~1ms from SM7):**
- `LED_DISPLAY` mode: Round-robin scan through 5 pins, set low for ON or high for OFF
- `ui_no_timer_scan` flag prevents scanning during `ui_update` to avoid glitches

#### Key State Machine (`key_handle_10ms`, called from timer ISR at 10ms)

```
State: key_cnt (press duration counter)
       key_click_cnt (click count within window)
       key_delay_ms (double-click timeout countdown)

Press down (!_KEY_LEVEL):
  key_cnt++ each 10ms
  key_cnt == 150 (1.5s) -> key_flag = 3 (long press), key_click_cnt = 0
  key_cnt == 1200 (12s) -> MCU_RST + clear power_on_magic (hard reset)
  key_cnt capped at 1800

Release (_KEY_LEVEL):
  if key_cnt in [3,50] (30-500ms valid press):
    First click: key_delay_ms = 50 (500ms window), key_click_cnt = 1
    Second click within window: key_flag = 2 (double click), reset
  key_cnt = 0

Timeout (key_delay_ms countdown):
  key_delay_ms-- each 10ms
  When reaches 0 with key_click_cnt > 0: key_flag = 1 (single click)
```

**Key Actions (processed in `ui_update` at 250ms):**

| key_flag | Action | Function |
|----------|--------|----------|
| 1 (single) | Restore from protection fault, clear lighting mode, clear wpc_disable, reset mini_current_mode | `key_sigle_click_process()` |
| 2 (double) | Enable lighting mode on active source ports, disable WPC | `key_double_click_process()` |
| 3 (long) | Toggle mini_current_mode for port 0 source | `key_long_click_process()` |

### 2.8 `app/gui.c` - I2C Slave Implementation (260 lines)

**I2C Slave Interrupt Handler (`apl_i2cs_GR03_int_handler`, line 71):**
- Triggered by I2CS peripheral interrupt
- Command byte: `[7]MOD [6:5]LEN [4:0]CMD`
  - MOD=1: Read (1 or 2 bytes from `app_reg_buff[addr]`)
  - MOD=0: Write (1 or 2 bytes to `app_reg_buff[addr]`)
- Register address from `GR02` field
- Max 2-byte transfers per interrupt

**Read Sync (`iic_read_info_sync`, called every 10ms):**
- Updates `app_reg_buff` with current sensor values
- tx_status bit encoding: `[7]err_any | [6]otp | [5]ovp | [4]fod | [0]rx_status`
- Protection flags checked: tdie_otp, tntc_otp, vbus_ovp, vpwr_ovp, q_fod, xfer_fod, plus tdie_utp, tntc_utp, isns_ocp, vbus_uvp, vbus_dpl, pout_opp

**Write Sync (`iic_write_info_sync`, called every 10ms):**
- Reads `master_msg` register for adapter capability notification
- If `ready == 1`: Parses voltage/current, determines adapter cap:
  - `>= 9V && > 1A`: `master_adaptor_cap = 2`, required_volt = 9000mV
  - Else: `master_adaptor_cap = 1`, required_volt = 5000mV
- `CUST_BEISI` conditional: Direct GPIO control for custom hardware

### 2.10 `app/sleep.c` - Sleep/Wake Implementation (1286 lines)

This is the most complex module. The system uses **reset-based sleep** (MCU resets after each sleep cycle).

#### Sleep State Machine

```
                    RST_vCheck()
                         |
                   +-----+-----+
                   |  RST_SRC?  |
          +--------+-----+-----+---------+
          |        |           |          |
    WARMUP_DONE  1P_TIMER    GPIO    PROTOCOL
    (power-on)  (periodic)  (key/IRQ) (TCPC)
          |        |           |          |
     Full boot  tc_check_wake  Clear    Full boot
                 + Q detect   lighting
                     |
                +----+----+
                | wake? |
           +----+    +----+
           NO        YES
           |          |
     SLP_vSleepToSleep  Full boot
```

#### Normal-to-Sleep (`SLP_vNormalToSleep`, line 50)

**Step-by-step sequence:**
1. `VIC_vModuleDisable()` - Disable all interrupts
2. Feed watchdog
3. Put authentication IC to sleep (`TMC_Power_Down()` or `fm1210_sleep()`)
4. Configure `SYS->PWR_CTRL`: SLEEP_MODE_EN=0, GPIO_WKUP_DIS=0
5. Clear sleep state counters: rd0/1_cnt, light0/1_cnt, SOC_SleepTime_s, reset_magicode, sleep_q_times
6. **CC pin setup for sleep:**
   - If lighting_mode or dead_bat_with_snk: Set CC to RP_DEF (maintain source connection)
   - Else: Set CC to OPEN (disconnect)
7. **Buckboost IC sleep:**
   - NU6801: Multi-step sequence with INT mask, BUBO_CTRL manipulation, hidden register writes (0x50/0x51/0x63), 500ms total delay with key-press reset check at each 10ms
   - NU6805: Disable B port IRQ, disable discharge/powerpath/mode, clear IRQ events, set Indt_Control=0x03
8. USB XGB sleep (if enabled)
9. **Peripheral shutdown:**
   - TCPC: CCA_CTRL=0, CCB_CTRL=0, RXD_CTRL=0, QDT_CTRL=0
   - ADC: BADC=0, EADC=0
   - I2CS=0, all BPWM=0, all EPWM=0
   - TCPC PHY=0, DPDM=0
   - FMC disabled, all ECAP=0
   - DPDM_QC_SINK=0, I2CM=0
   - SYS: CLK_CTRL=0, PRO_CTRL=0, XTAL_EN=0, PVD_EN=0
   - All TMR=0
   - All UART=0
10. GPIO: `hal_gpio_init_default()`, configure key wake-up (GPC PIN6, interrupt-on-toggle)
11. NU6801: Configure charger IRQ wake-up (GPD PIN1)
12. Stop PWM, reset NU103x, enable LPM
13. **TMR0 wake-up timer:** `LOAD_CNT = 16 * 100 * 1 - 1` (100ms first wake), LIRC 64K source, one-shot mode
14. **GPIO wake-up workaround:** Briefly set GPIO_WKUP_DIS=1, set pins to mode 0b11, stop WDT, 100us delay, SLEEP_MODE_EN=1, restore GPIO_WKUP_DIS=0, restore pin modes
15. 10ms delay, then `MCU_RST = 1`

#### Sleep-to-Sleep (`SLP_vSleepToSleep`, line 355)

Lighter version - skips auth IC sleep, buckboost manipulation. Key differences:
- Increments `SOC_SleepTime_s` (capped at 10000)
- **Adaptive sleep timer:**
  - First 20 cycles (`sleep_q_times < 20`): 50ms (fast Q charge)
  - Idle (no rd/light counters): 1200ms (1.2s long sleep)
  - CC active (rd_cnt or light_cnt > 0): 150ms (fast CC poll)
- NU6805 specific: After 25 seconds, enable charger IRQ wake-up; before 25s, actively disable buckboost discharge/powerpath/mode
- Same peripheral shutdown and GPIO workaround as Normal->Sleep

#### Sleep Q Detection (`SLP_u8SleepModeQDetect`, line 511)

During sleep, periodically checks Q-factor to detect wireless receiver placement.

**Sequence:**
1. Configure GPIO for EPWM1/EPWM2/ECAP1/ECAP2
2. Reset NU103x, disable LPM, run `fml_qdt_detect()` to measure Q and frequency
3. First 20 cycles: Skip detection (`sleep_q_times++`)
4. State-based wake decision on `ptx_idle_phase_status`:

| State | Wake Condition |
|-------|----------------|
| `WPC_IDLE_STAT_STANDBY` | Q drop OR F drop below threshold |
| `WPC_IDLE_STAT_XER_COM` | Q/F return to normal -> go to STANDBY; else timeout at 11 minutes |
| `WPC_IDLE_STAT_XER_FOD/QDT_FOD/LAR_MET/EPT_ERR` | Q/F return normal 3 consecutive times -> STANDBY |
| `WPC_IDLE_STAT_EPT_RES/EPT_REP` | Immediately go to STANDBY |

#### Reset Check (`RST_vCheck`, line 624)

Called at boot to determine wake-up source:

| RST_SRC | Meaning | Action |
|---------|---------|--------|
| `RST_SRC_1PTIMER` (2) | Timer wake | Feed WDT, compute sleep_ms, update RTC, check `reset_magicode==55` (skip sleep), else: `tc_check_wake()` then Q detect, go back to sleep or full boot |
| `RST_SRC_GPIO` (3) | Key press or charger IRQ | Clear IRQ events, clear ship_mode_cnt, clear lighting mode, enable WPC |
| `RST_SRC_PROTOCOL` (4) | TCPC wake | Clear SLEEP_MODE_EN |
| `RST_SRC_WARMUP_DONE` (1) | Power-on | Clear power_on_magic, full boot |

**RTC Compensation in sleep:** `sleep_ms = (TMR0_LOAD_CNT >> 4) - 30` -> adds to `Bat_RTC_Milliseconds/Seconds`

#### Type-C Wake Check (`tc_check_wake`, line 730)

4-step CC probe sequence during sleep:
1. **Step 0**: Check if lighting/dead-bat ports still have Rd (source connected). If disconnected 10 times -> clear lighting mode
2. **Step 1**: Set CC to RD, delay 1.7ms, check for Rp (charger detected -> SNK wake)
3. **Step 2**: Set CC to RP_1_5, delay 1.7ms, check for Rd (device detected -> SRC wake)
4. **Step 3**: Repeat step 1 for confirmation

Return bitmask: `TC_WAKE_TC0_SRC=0x08, TC_WAKE_TC0_SNK=0x04, TC_WAKE_TC1_SRC=0x40, TC_WAKE_TC1_SNK=0x20, TC_WAKE_TC0_OUT=0x02, TC_WAKE_TC1_OUT=0x10`

    exception_counter: uint32_t
    write_ptr: uint32_t
    reserved: uint32_t
    records[5]: BatteryExceptionRecord_t  // 5 x 20B = 100B
    checksum: uint16_t
}

BatteryExceptionCache_t {
    status_flags: uint8_t       // bit0:cell1_tracking, bit1:cell2_tracking, bit2:temp_tracking,
                                // bit[5:3]:temp_event_type, bit[7:6]:charge_state
    cell1_max_voltage: uint16_t
    cell2_max_voltage: uint16_t
    max_temperature: int16_t
    ov_hour_start_seconds: uint32_t
    temp_hour_start_seconds: uint32_t
}
```

**Circular Buffer Logic:**
- `MAX_RECORDS = 5` records
- `write_ptr` wraps around modulo 5
- Each write: assigns `record_id = write_ptr`, stores record, increments `write_ptr`, increments `exception_counter` (capped at MAX_RECORDS)
- **Entire page erased and rewritten on each Flash save** (whole-structure write)

**Overvoltage Tracking (`process_cell_overvoltage`):**
1. **Onset (first detection):** Immediately write a record to Flash with current voltage
2. **Ongoing (within 1 hour):** Update RAM record only (no Flash write). Track max voltage
3. **1 hour passed:** If max increased, save to Flash and reset 1-hour window
4. **Recovery:** If max changed, final save to Flash, then clear tracking state

**Temperature Tracking (`battery_record_update_temperature`):**
- Same onset/ongoing/hourly/recovery pattern as overvoltage
- Uses NTC resistance -> temperature conversion via `ntc_to_temp()`
- Threshold: `CHRG_NTC_OT_VALUE` (regardless of charge/discharge mode per simplified implementation)

**Periodic Check (`battery_record_periodic_check`):**
- Called from 100ms APL timer
- Internal counter: Every 10 calls (1 second) -> check OV + temperature
- Prints current timestamp at each check

**RTC Time System:**
- `gd->Bat_RTC_Seconds`: Running seconds since epoch (2026-01-01 00:00:00)
- `gd->Bat_RTC_Milliseconds`: Sub-second precision (0-999)
- During sleep: Timer-based compensation adds sleep_ms to milliseconds/seconds
- `seconds_to_timestamp()`: Converts to Y/M/D H:M:S from 2026 base year

## 3. Execution Flow

### 3.1 Initialization Sequence

```
main()
  -> RST_vCheck()                    // Determine wake-up source
       -> [RST_SRC handling]         // May go back to sleep
  -> apl_task_init()
       -> fml_tntc/tdie/isns/vbus/vpwr/pout protection inits
       -> led_init() -> _SET_ALL_PINS_IN_PUT()
       -> osal_task_handler_reg(APL_TASK, apl_task_event_handler)
       -> Start 4 timers:
            APP_250ms_TIMER(0) -> 250ms -> APL_EVT_250ms_POLL
            APP_100ms_TIMER(1) -> 100ms -> APL_EVT_100ms_POLL
            APP_010ms_TIMER(0) -> 10ms  -> APL_EVT_010ms_POLL
            APP_005ms_TIMER(30) -> 5ms  -> APL_EVT_005ms_POLL
  -> APP_vInit()                     // UART RX init
  -> apl_gui_init()                  // I2C slave callback
  -> battery_record_init()           // Flash log init
```

### 3.2 Periodic Task Execution

```
Timer ISR (1ms tick)
  -> key_handle_10ms() [every 10ms]      // Key state machine in ISR context
  -> Bat_RTC_Seconds++ [every 1000ms]    // RTC tick

OSAL dispatch -> apl_task_event_handler()
  -> APL_EVT_005ms_POLL [5ms]            // IPGA measurement
  -> APL_EVT_010ms_POLL [10ms]           // Sensor + protection + I2C
  -> APL_EVT_100ms_POLL [100ms]          // Temperature + battery record
  -> APL_EVT_250ms_POLL [250ms]          // UI + SOC + DMO
```

### 3.3 Sleep Entry Flow

```
wpc_idle.c: idle_to_sleep_cnt > 100 (25 seconds at 250ms)
  -> SLP_vNormalToSleep()
       -> Disable interrupts
       -> Sleep auth IC
       -> Configure CC (OPEN or RP_DEF)
       -> Sleep buckboost IC (500ms sequence for NU6801)
       -> Shutdown all peripherals
       -> Configure wake-up sources (key GPIO, charger IRQ, TMR0 100ms)
       -> Enter sleep (SLEEP_MODE_EN=1)
       -> MCU_RST after wake
```

### 3.4 Wake-Up Flow (Timer)

```
MCU Reset -> RST_vCheck()
  -> RST_SRC == RST_SRC_1PTIMER
       -> Compute sleep_ms, update RTC
       -> tc_check_wake() [4-step CC probe]
            -> Returns bitmask of detected connections
            -> If any connection detected -> full boot
       -> SLP_u8SleepModeQDetect()
            -> Measure Q/F via QDT
            -> Compare with base values + thresholds
            -> If Q-change detected -> full boot
       -> Else SLP_vSleepToSleep() [back to sleep with adaptive timer]
```

## 6. Expert Insights

### 6.1 Design Patterns

1. **Reset-Based Sleep**: The MCU performs a full reset on each sleep cycle. Persistent state survives in RAM (non-initialized `.noinit` section via `gd` pointer). This avoids complex peripheral re-initialization on wake but requires careful management of `reset_magicode` and other magic values.

2. **Adaptive Sleep Timer**: Sleep intervals adapt to activity level - fast during Q-detection startup (50ms), medium during CC polling (150ms), slow during idle (1.2s). This balances power consumption vs responsiveness.

3. **1-Hour Flash Write Batching**: Battery exception records accumulate in RAM during tracking, only flushing to Flash every hour or on recovery. This reduces Flash wear while maintaining data integrity.

4. **SOC Gradual Display**: Rather than jumping SOC directly to the BMS value, the display increments/decrements by 1% every 15 seconds. This provides a smooth user experience.

5. **Charlieplexed LED Scanning**: 5 GPIOs drive 5 LEDs with time-multiplexed scanning at 1ms rate, using input/output mode switching to create virtual ground/VCC for each LED.

### 6.2 Potential Risks / Bug Patterns

1. **ISNS Median Filter Truncation** (app.c:194): The bubble sort uses `uint8_t temp` for swap but `u16IsnsTmp` is `uint16_t[]`. Values > 255 will be truncated during swap, corrupting the sort. This is a confirmed bug.

2. **Race Condition on `key_flag`** (led.c:16,726): `key_flag` is written by `key_handle_10ms()` in timer ISR context and read/cleared in `ui_update()` in task context. No atomic access or critical section. If ISR fires between read and clear, a key event could be lost.

3. **`flash_flag` Incomplete Coverage** (led.c:600-624): When all ports disconnect (no source, no sink, no WPC), `flash_flag` stays at whatever previous value if none of the conditions reset it. Specifically, if last state was `flash_flag=1` (charging), disconnecting the charger with SOC > 5% doesn't clear it because the "else" branch only executes if no port is source.

4. **Sleep RTC Drift**: `sleep_ms = (tmr_cnt >> 4) - 30` assumes LIRC at exactly 64KHz / 16K after prescaler. LIRC accuracy is typically +/-10%, causing cumulative RTC drift over long sleep periods.

5. **Logical NOT vs Bitwise NOT** (sleep.c:687,699): `SYS->PWR_CTRL.WORD &= !SYS_PWR_CTRL_SLEEP_MODE_EN_Msk` uses logical NOT `!` instead of bitwise NOT `~`. If the mask is non-zero, `!mask = 0`, clearing the entire register. Should be `&= ~SYS_PWR_CTRL_SLEEP_MODE_EN_Msk`.

6. **NU6801 Sleep Sequence Fragility**: The 0x50/0x51/0x63 register writes (sleep.c:101-108) appear to be undocumented workaround writes. The 50ms x 4 polling loops check key press but if I2C communication fails, no error handling exists.

7. **`iic_write_info_sync` Dead Code** (gui.c:240-257): `CUST_BEISI` conditional references `io_ctl_msg` which is only declared as a comment (line 197). If `CUST_BEISI` is ever defined, this will fail to compile.

8. **Overvoltage Per-Cell Estimation** (bat_record.c:387-388): `cell1_voltage = total_voltage / 2` is a rough approximation for 2S battery. Real cell voltages can differ significantly. For NU6801 single battery, only cell 1 is tracked.

9. **`one_min_cnt > 60`** (led.c:529): Comment says "15s" but at 250ms period, 60 * 250ms = 15 seconds. However the variable name says "one_min_cnt" which is misleading. This is not 1 minute.

10. **Concurrent Flash Access Risk**: `save_storage_to_flash()` erases an entire page then writes sequentially. If interrupted (by watchdog timeout or power loss), data is lost. No double-buffering or wear-leveling.

### 6.3 Debugging Guide

| Symptom | Check | Log Pattern |
|---------|-------|-------------|
| LEDs not lighting | `_SET_ALL_PINS_IN_PUT()` called? `ui_no_timer_scan` stuck? | `LED ram-> %d SOC %d` |
| SOC stuck at 0 | `real_soc_obtained`, `SOCPack_DisplaySOC_pct > 0`? | `update real show soc` |
| SOC jumps | `one_min_cnt` period, charge/discharge mode detection | `real show=%d SOC display=%d` |
| Won't sleep | `idle_to_sleep_cnt` reset by port_manager events | `idle cnt [%d]` |
| Won't wake from key | GPC PIN6 ITEN configured? GPIO mode correct? | `sleep check- GPIO` |
| Won't wake from charger | NU6801: GPD PIN1 ITEN? NU6805: `SOC_SleepTime_s >= 25`? | `sleep check- GPIO` |
| Q-detect false wake | `sleep_q_68nf_thd`, `sleep_f_68nf_thd` (both 0!) | `sleep: [phase] [q:val,base,diff] [f:val,base,diff]` |
| Battery record lost | Flash checksum error? `MAGIC_VALUE` mismatch? | `log: Checksum error...` or `log, initializing...` |
| I2C slave no response | `apl_gui_init()` called? I2CS interrupt enabled? | - |
| IPGA reading wrong | `pga_offset` calibrated? `Rsns` correct? | Check `gd->ipga` |
| Key not detected | Timer ISR calling `key_handle_10ms`? `_KEY_LEVEL` reading? | `key single/double/long click` |
| Protection not triggering | `fml_*_init()` called? Threshold values correct? | Check `prot_sts.*` flags |

**Key Debug Variables:**
- `gd->real_soc_show` - Displayed SOC
- `gd->idle_to_sleep_cnt` - Sleep countdown
- `gd->ptx_idle_phase_status` - WPC idle state (affects Q-detect behavior)
- `gd->Bat_RTC_Seconds` - RTC time
- `soc_show_ram_led` - LED bit pattern (static in led.c)
- `flash_flag` - LED blink mode (static in led.c)
- `key_flag` - Pending key event
- `g_record_storage` - Battery log RAM cache (via `ap->record_storage`)

### 6.4 Customization Hotspots

1. **LED Pattern** (led.c:203-218): Change `batt_level_table[]` and `BATT_ENERGY_LEVEL*` for different SOC-to-LED mappings.

2. **Key Behavior** (led.c:644-698): Modify `key_sigle/double/long_click_process()` for different user interactions.

3. **Sleep Timing** (sleep.c:297,367,373,375): Adjust TMR0 LOAD_CNT values for different sleep/wake trade-offs.

4. **Q-Wake Thresholds** (sleep.c:39-40): `sleep_q_68nf_thd` and `sleep_f_68nf_thd` are currently **both 0** - meaning Q-detect uses raw base values. Must be calibrated per coil/capacitor combination.

5. **Battery Record Settings** (config.h:91-92, bat_record.h, g_data.h): `MAX_RECORDS=5`, `OVER_VOLTAGE_THRESHOLD=4200`, `CHRG_NTC_OT_VALUE`.

6. **Protection Thresholds**: All `fml_*_init()` functions take thresholds - traced back to ap_t MTP parameters.

7. **IPGA Calibration** (app.c:308): `pga_gain_cnt > 80` (8s idle time before offset cal). `Rsns` in config.h.

8. **I2C Register Map** (gui.c): Add new registers by extending `iic_xfer_info_idx_t` enum and updating read/write sync functions.

9. **RTC Base Year** (bat_record.c:68): Hardcoded to 2026. Change for different epoch.

10. **SOC Display Rate** (led.c:529): `one_min_cnt > 60` at 250ms = 15s per SOC step. Adjust for faster/slower display tracking.
