## 1. Module Overview

The FML (Firmware Middleware Layer) subsystem is the **foundational layer** of the NU17112 powerbank firmware. It owns:

1. **System Entry** (`main()`) - The entire boot sequence orchestrator
2. **Global Data Structures** (`ap_t`, `gd_t`, `lib_para`) - Central shared data for all modules
3. **BSP Initialization** - All HAL peripheral setup
4. **FML_TASK** - Gauge bridging (BMS SOC calculation) and HID report updates
5. **Adapter Management** - Adapter type classification and voltage control bridge

## 3. Core Logic Deep Dive

### 3.1 main() Initialization Sequence (`app/main.c:41-137`)

```
main()
  1. VIC_vModuleDisable()            -- Disable all interrupts
  2. hal_wdt_init()                  -- Watchdog timer init
  3. RST_vCheck()                    -- Reset source check
  4. ap_data_init()                  -- Flash->RAM config, protection thresholds
  5. gd_data_init()                  -- Runtime data init (cold/warm boot aware)
  6. lib_para_init()                 -- Feature flags from #defines
  7. fml_bsp_init()                  -- All HAL peripherals
  8. battery_record_init()           -- [conditional: CONFIG_NEW_CCC_LOG_ENABLE]
  9. apl_gui_init()                  -- LED/GUI init
  10. gd->adp.adp_type = EADP_TYPE_IDUNKNOWN  -- Reset adapter type
  11. fml_nu103x_por_init()           -- NU103x WPC coil driver power-on-reset
  12. hal_wdt_feed()                  -- Feed watchdog
  13. [if NU6805] delay_1ms(500) + hal_wdt_feed()  -- NU6805 needs 500ms startup
  14. Auth SE init:
      - [auth_seic_type==1] t91206_init() + read cert/hash/id
      - [else] fm1210_init() + read cert/hash/id
  15. hal_wdt_feed()
  16. fml_adp_init()                  -- Default adapter: POWERBANK_WIRELESS_ONLY
  17. [if CONFIG_SUPPORT_IPGA] PGA offset calibration
  18. osal_init()                     -- OSAL kernel init
  19. Task registration sequence:
      a. apl_task_init()             -- APL_TASK (4)
      b. buckboost_task_init()       -- BUCKBOOST_TASK (5)
      c. tcpm_task_init()            -- USB_TASK (2)
      d. usb_dpdm_task_init()        -- USB_DPDM_TASK (6)
      e. fml_task_init()             -- FML_TASK (1)
      f. [if CONFIG_WPC_SUPPORT] wpc_task_init()  -- WPC_TASK (3)
      g. port_manager_task_init()    -- PORT_MANAGER_TASK (7)
  20. osal_start_system()             -- Start OSAL scheduler (never returns)
```

**Key insight**: The init order matters. Data structures (ap, gd, lib_para) must be initialized before BSP, which must be initialized before any task that uses peripherals. Auth SE init involves I2C and takes >100ms with watchdog feeds.

### 3.4 gd_data_init() - Runtime Data Init (`g_data.c:188-243`)

**Cold vs Warm boot detection**: Uses `gd->power_on_magic` at a fixed RAM address.
- If `power_on_magic != 0xaaaa` => **Cold boot** (first power-on or full reset)
- If `power_on_magic == 0xaaaa` => **Warm boot** (wake from sleep, retains certain fields)

**Cold boot actions**:
```
  - Clear RAM from G_DATA_RAM_ADDR_BASE to &gd->resverd_reset (partial clear!)
  - gd->tc0_lighting_mode = 0, gd->tc1_lighting_mode = 0
  - gd->bat_dead_flag_with_snk0/1 = 0
  - gd->wpc_disable = 0
  - gd->real_soc_show = 0, gd->real_soc_obtained = 0
  - gd->SOC_RawSOC_mpct = 0, gd->SOC_SleepTime_s = 2000
  - tc_power_on = true          -- Signals typec.c to force dead-battery SNK attach
  - power_on_cnt = 40           -- Skip gauge for 40 * 100ms = 4 seconds
  - gd->Battery_cycle_count = 0, gd->Battery_charger_cnt = 0
  - gd->Bat_RTC_Seconds = compile-time RTC default (2026-02-03 16:26:00)
  - gd->power_on_magic = 0xaaaa -- Mark as initialized
```

**Warm boot**: Skips all above, preserves `tc0/1_lighting_mode`, `wpc_disable`, SOC, cycle count, RTC seconds, etc. Only the region before `resverd_reset` is zeroed (wireless charging transient state).

**Critical design**: The partial RAM clear (`up to &gd->resverd_reset`) means fields AFTER `resverd_reset` in `gd_t` survive warm boot. This includes: `power_on_magic`, `tc0/1_lighting_mode`, `wpc_disable`, `real_soc_show`, `bat_dead_flag`, `Battery_cycle_count`, `Bat_RTC_Seconds`, `SOC_RawSOC_mpct`, `SOC_SleepTime_s`, `ship_mode_cnt`.

### 3.6 FML_TASK Event Handler (`_fml.c:27-70`)

```
fml_task_event_handler(event):
  switch(event):
    case FML_EVT_ASK_INT_RECVD:       -- WPC ASK decode interrupt
      fml_ask_decode()                 -- Process ASK demodulation (in lib/ask.c)

    case APL_EVT_GAUGE:                -- Every 100ms from GAUGE_TIMER
      if (power_on_cnt > 0):
        power_on_cnt--                 -- Skip gauge for first 4 seconds
      else:
        SigPr_CellTemps_C_s = 25      -- Fixed 25C temperature input
        SigPr_CellVolts_mV_s = g_buckboost.adc_vbat
        SigPr_PackCurr_mA_s = g_buckboost.adc_ibat
        Cyclic()                       -- Run BMS fixed-point SOC algorithm

        // Battery health calculations
        if (Battery_cycle_count <= 50):
          Bat_Rdc = P_R0Dsg_mOhm[0]   -- Base internal resistance
          Bat_SoH = 100                -- Full health
        else:
          Bat_Rdc = base + base * (cycles - 50) * 5 / 10000  -- Linear degradation
          Bat_SoH = 100 - (cycles - 50) * 5 / 100            -- Linear SOH decay
          if (Bat_SoH < 0) Bat_SoH = 0

    case APL_HID_REPORT:               -- Every 47ms from USB_WB7720_TIMER
      [if CONFIG_USE_USB_XGB]
        ubsd_wb7720_report_update()    -- Write battery data to WB7720 via I2C
```

### 3.7 WB7720 HID Report Update (`_fml.c:115-181`)

Round-robin I2C writes to WB7720 HID gauge chip at address 0x21. Uses a `static cnt` counter cycling 0-9 (with 2 idle slots at cnt=8,9):

| cnt | Register | Data | Size |
|-----|----------|------|------|
| 0 | 0x00 (SOC_pct) | `gd->real_soc_show` | 1 byte |
| 1 | 0x01 (Capacity_mAh) | 5200 (hardcoded) | 2 bytes |
| 2 | 0x05 (VBAT_mV) | `adc_vbat - adc_ibat * 8 / 1000` (IR compensation) | 2 bytes |
| 3 | 0x07 (IBAT_mA) | `adc_ibat` | 2 bytes |
| 4 | 0x09 (TEMP_dC) | `ntc_to_temp(adc_tbat1)` (also sets `g_buckboost.batTemp`) | 2 bytes |
| 5 | 0x0B (CycleCount) | `gd->Battery_cycle_count` | 2 bytes |
| 6 | 0x0D (R_internal_mOhm) | `gd->Bat_Rdc` | 2 bytes |
| 7 | 0x0F (SOH_pct_x100) | `gd->Bat_SoH` | 2 bytes |
| 8-9 | (idle) | - | - |

**Full report cycle**: 10 * 47ms = 470ms per complete update.

### 3.8 NTC Temperature Conversion (`_fml.c:73-112`)

**NTC 3435 lookup table**: 111 entries covering -19C to +91C. Values are descending (NTC resistance decreases with temperature).

**Algorithm**: Binary search on the descending table (reverses left/right logic). Returns index - 19 to get Celsius.

**Comment**: "6801, needs change if 6805" - the NTC table may differ for NU6805 variant.

### 3.9 Adapter Type Management (`adp.c`)

**`fml_adp_init()`**: Sets default powerbank adapter type:
- If `ONLY7_5W_ENALBE` (currently 0): `EADP_TYPE_POWERBANK_WIRELESS_ONLY`, 5000-19500mV, 15W
- If `ONLY7_5W_ENALBE` = 1: Same type, 5000-13000mV, 10W
- Sets `ap->vbus_uvp_thd = 4000` (override from default 7800)

**`fml_adp_type_set()`**: Updates `gd->adp` struct and sets `gd->adp_type_upd = 1` flag if any field changed. This flag triggers WPC adapter negotiation events downstream.

**`fml_adp_volt_set()`**: Dispatches voltage change request based on current adapter type:
- `EADP_TYPE_POWERBANK_WIRELESS_ONLY` or `EADP_TYPE_POWERBANK_PPS`: Sets `qi_volt` and triggers `TCPM_EVT_QI_SET_VOLT` on USB_TASK
- All other adapter types: No-op (handled directly by USB PD or QC)

## 7. Expert Insights

### 7.1 Design Decisions

1. **Flash-backed configuration with RAM override**: `ap_data_init()` copies 256 bytes from Flash then overwrites most values with hardcoded constants. This suggests the Flash values are legacy/calibration data (Q-factor, frequency) while protection thresholds are firmware-controlled. The design allows field calibration of analog parameters while keeping safety thresholds fixed.

2. **Partial RAM clear for warm-boot persistence**: `gd_data_init()` only clears up to `&gd->resverd_reset`, preserving fields after it across sleep/wake cycles. This is a deliberate design to maintain SOC, lighting mode, cycle count, and RTC through low-power sleep. The `power_on_magic` sentinel (0xaaaa) distinguishes cold vs warm boot.

3. **Temperature hardcoded to 25C**: `SigPr_CellTemps_C_s = 25` in the gauge bridge means the BMS algorithm always sees 25C regardless of actual battery temperature. This simplifies the SOC model but reduces accuracy for temperature-dependent capacity estimation.

4. **WB7720 round-robin with idle slots**: The HID report uses 10 counter slots but only 8 have data (cnt 8-9 are idle). This provides a ~94ms gap every 470ms, possibly to avoid I2C bus contention.

5. **lib_para as compile-to-runtime bridge**: The `lib_para_sts` bitfield exists because library code (`.lib` files) cannot use `#ifdef` at compile time - it needs runtime flags. This pattern decouples feature configuration from precompiled libraries.

### 7.2 Risk Identification

1. **power_on_cnt race condition** (`g_data.c:62`, `_fml.c:35`, `hal/nu6801.c:119-120`): `power_on_cnt` is accessed from both `fml_task_event_handler()` (FML_TASK context) and `nu6801.c` (BUCKBOOST_TASK context). No mutex or volatile qualifier. Since OSAL is cooperative (no preemption between tasks), this is safe only if tasks don't interrupt each other.

2. **Battery_cycle_count overflow** (`g_data.h:526`): `uint8_t` type limits to 255 cycles. Powerbank batteries typically last 500+ cycles. The Rdc/SoH calculation uses `(cycle_count - 50)` which wraps around at 255, producing incorrect health estimates after 255 cycles.

3. **Bat_SoH can go negative** (`_fml.c:55-56`): Formula `100 - (cycles - 50) * 5 / 100` goes negative when cycles > 2050, but since uint8_t wraps at 255, the actual risk is at 255 cycles: SoH = 100 - 205*5/100 = 100 - 10 = 90%. The `if(Bat_SoH < 0)` check is on `int8_t` (-128 to 127), so intermediate overflow is possible. With uint8_t cycle_count max=255, max degradation = (255-50)*5/100 = 10.25, so SoH = 89.75, truncated to 89. Actually safe in practice.

4. **NTC table binary search on descending data** (`_fml.c:88-107`): The `binary_search` function is adapted for descending-ordered data (reverses left/right logic). The comment is garbled (encoding issue). If someone modifies this assuming ascending order, it will return incorrect temperatures.

5. **`vbus_uvp_thd` double-write** (`g_data.c:99` sets 7800, then `adp.c:55` overrides to 4000): The final value is 4000mV, but someone reading only `ap_data_init()` would think it's 7800mV. This hidden override could cause confusion during debugging.

6. **gd_t struct field ordering is fragile**: Fields after `resverd_reset` survive sleep. Adding new fields requires careful placement. If a new field is added before `resverd_reset`, it gets cleared on warm boot. If added after, it persists. No documentation in code marks this boundary.

7. **WB7720 battery capacity hardcoded to 5200mAh** (`_fml.c:141`): This should match the actual battery but is not derived from any configuration parameter.

8. **Product info Flash operations** (`g_data.c:323-339`): `product_info_write()` erases an entire Flash page before writing. If power is lost during write, the entire page is lost. No wear-leveling or double-buffering.

### 7.3 Bug Patterns to Watch

1. **Q-factor validation inconsistency** (`g_data.c:146,158`): First check is `(*pdest0 < 0) || (*pdest0 > 500)` for Q but same `*pdest0` pointer is used for second check `(*pdest0 < 0) || (*pdest0 > 1500)` for frequency. The second check should use `*pdest1`. Current code correctly uses `*pdest1` for the assignment (`ap->fs_base_value = *pdest1`) but validates against `*pdest0`. This is a **confirmed bug**: frequency validation uses wrong pointer.

2. **`SigPr_CellTemps_C_s = 25` type mismatch**: If the BMS expects a different unit (e.g., 0.1C), passing 25 means 25C or 2.5C depending on convention. Need to verify BMS input format.

3. **Conditional compilation fragmentation**: `CONFIG_NEW_CCC_LOG_ENABLE` adds ~130 bytes to `ap_t` (`exception_cache` + `record_storage`). If this define changes, the Flash-to-RAM copy size (256 bytes) doesn't adjust, potentially corrupting data layout.

### 7.4 Debugging Guide

| Symptom | Check | Key Variables |
|---------|-------|---------------|
| SOC not updating | `power_on_cnt` still > 0? GAUGE_TIMER running? | `power_on_cnt`, `gd->real_soc_show` |
| Wrong temperature | NTC table correct for hardware? `adc_tbat1` reading? | `g_buckboost.adc_tbat1`, `g_buckboost.batTemp` |
| WB7720 not responding | I2C address 0x21? `CONFIG_USE_USB_XGB` enabled? | I2C bus, `hal_i2cm_write` return |
| Protection not working | `ap->xxx_dis` flag set to 1? Threshold correct? | `ap->tntc_otp_dis`, `ap->vbus_ovp_thd` etc. |
| Warm boot data lost | Field above `resverd_reset`? `power_on_magic` corrupted? | `gd->power_on_magic`, RAM contents |
| Adapter type wrong | `fml_adp_type_set` called with stale params? `adp_type_upd` flag? | `gd->adp`, `gd->adp_type_upd` |
| Cold boot every time | RAM corruption? `power_on_magic` at wrong address? | 0x20000200 + offset of `power_on_magic` |
| Q/freq calibration bad | Flash values at 0x1600 valid? Validation bug (see 7.3 #1) | `ap->q_factor_base_value`, `ap->fs_base_value` |

**Recommended breakpoints**:
- `g_data.c:202` - Check `power_on_magic` value at boot
- `_fml.c:44` - Verify gauge inputs before `Cyclic()`
- `adp.c:13-16` - Track adapter type changes
- `bsp.c:36` - Verify BSP init completion

### 7.5 Customization Hotspots

1. **Protection thresholds** (`g_data.c:74-112`): All `_thd` and `_hys` values. Most common customization for different battery/hardware specs.

2. **Battery capacity** (`_fml.c:141`): Hardcoded 5200mAh. Must match actual battery.

3. **NTC table** (`_fml.c:73-86`): Must match actual NTC thermistor (currently 3435 beta). Different NTC requires different table.

4. **Gauge period** (`_fml.h:11`): `T_GAUGE = 100` ms. Affects SOC update rate and power consumption.

5. **Adapter default** (`adp.c:48-52`): Initial adapter type and power limits. Depends on hardware design (7.5W vs 15W).

6. **Auth SE type** (`g_data.c:117`): `auth_seic_type = 0` selects FM1210. Change to 1 for T91206, 2 for CIU98.

7. **Feature flags** (`config.h:69-74`): `CONFIG_TYPECA_SUPPORT`, `CONFIG_TYPECB_SUPPORT`, `CONFIG_AFC/FCP/SCP_SOURCE_SUPPORT`. These feed into `lib_para` and control library behavior.

8. **Dead battery voltage** (`config.h:13`): `CONFIG_NU6801_BATLOW_VOLT = 2800` mV. Affects Type-C dead battery handling.

9. **Digital ping parameters** (`g_data.c:126-144`): Voltage/period/duty/phase for 5V/6V/9V/11V ping modes. Critical for WPC interoperability.

10. **RTC default time** (`config.h:97-103`): Compile-time RTC initialization. Relevant for battery exception logging timestamps.
