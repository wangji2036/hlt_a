## 设计意图与不变约束 (Design Rationale & Invariants)

> 这里记录的是「为什么」，不是「是什么」。「是什么」应当读代码。
> 参考完整文档: `docs/HAL_GUIDE.md`

### [D-001] 软 WDT 复位前主动清除 power_on_magic，强制冷启动

**原则**: `soft_wdt_reset()` 在调用 `MCU_RST()` 之前，**必须先**将 `gd->power_on_magic` 清零。这不是 bug，不能去掉。

**原因**: 任何导致看门狗超时的原因（主循环卡住、死循环、I2C 阻塞）都说明系统运行时状态已经不可信。如果不清除魔数，MCU 复位后 RAM 内容可能保留，系统误认为这是正常睡眠唤醒（热启动），用被污染的运行时状态（PID 积分项、WPC 协议相位、端口状态机）继续运行，产生难以复现的行为异常。强制冷启动代价小但安全。

**推论**: 不能通过"让 WDT 超时"来实现"保留部分状态的软复位"。需要保留状态的复位（睡眠唤醒）必须通过正常路径：先设置 `power_on_magic = 0xaaaa`，再调用 `MCU_RST()`。

### [D-002] 弱符号 ISR 模式：HAL 提供安全网，域模块拥有中断

**原则**: `hal/isr.c` 声明所有 26 个 ISR 为 `__attribute__((isr, weak))`。域模块（WPC/USB/BuckBoost）提供强符号实现，链接器自动覆盖弱符号。HAL 不需要知道哪些 ISR 被使用，也不需要注册回调。

**原因**: 嵌入式系统中中断处理函数必须在链接时静态绑定。弱符号模式允许域模块"认领"自己需要的中断，而不需要修改 HAL 代码。未被认领的中断有弱符号默认实现（空函数）作为安全网，不会因空向量表项而崩溃。

**推论**: 新增外设驱动时，只需在域模块的 `.c` 文件中实现对应名字的 ISR 函数即可（强符号自动覆盖弱符号）。不需要在 `isr.c` 中注册或修改任何内容。如果 ISR 名字拼错，链接器不会报错（弱符号仍然有效），中断永远不会到达预期处理函数——这是新驱动调试时的常见陷阱。

### [D-003] OSAL 事件 bit 编号即优先级，低位优先

**原则**: OSAL 使用 `bit_map[]` 查找表找最低置位 bit，最低位（bit 0）事件最先处理。定义 Task 事件枚举时，紧急事件必须放低位 bit。

**原因**: CK802 没有硬件 CTZ 指令，查表是 O(1) 找最低位的实用方法。选择最低位优先而非最高位优先，使得新增的非紧急事件可以安全地追加到高位，不影响已有的低位优先级。

**推论**: 如果某个事件处理比预期晚，首先检查它的 bit 编号是否比其他同时触发的事件更高。调整事件枚举顺序是解决事件优先级问题的正确手段，而不是修改 OSAL 调度逻辑。

### [D-004] OSAL 协作式调度：每次迭代只处理一个事件，任何阻塞都影响全局

**原则**: `osal_start_system()` 主循环每次迭代每个 Task 最多处理一个事件。Task 的事件处理函数必须快速返回（< 100ms），绝对不能在处理函数内等待硬件响应、轮询标志位或执行长时间延迟。

**原因**: 平台无 RTOS 抢占，所有 Task 共享同一个 CPU 执行流。一个 Task 事件处理函数占用 CPU，其他所有 Task 都在等待。超过 850ms 会触发软 WDT 复位。超过 10ms 会导致 USB PD 时序异常（TMR1 ISR 仍然运行，但 `usb_pdlib_timer_update()` 的时基累积误差增大）。

**推论**: 需要等待外设响应时（I2C 读取、ADC 采样稳定），应使用定时器分帧：启动操作，设置定时器，返回；定时器到期后再读取结果。任何在 Task 处理函数中看到的 `while(flag)` 轮询，都是架构风险。

### [D-005] TMR1 是多功能节拍，停止它会同时破坏 USB PD 时基和 UI

**原则**: TMR1（1ms 周期）在 ISR 中同时驱动 OSAL 时基（`sys_ticks++`）、USB PD 协议时基（`usb_pdlib_timer_update()`）和 UI 刷新/按键去抖（每 10ms）。它在系统运行期间必须始终运行。

**原因**: 将三个不同频率的需求（1ms 时基、USB PD 心跳、10ms UI）合并到一个定时器 ISR，减少了硬件定时器资源消耗（NU17112 只有 4 个硬件定时器，TMR0/2/3 各有专用角色）。代价是 TMR1 不可停用。

**推论**: 任何节能优化（关闭定时器降频）不能针对 TMR1。调试时若需要暂停 OSAL 调度（例如在 JTAG 断点后），需要理解 TMR1 ISR 仍在运行，USB PD 可能因超时而断开。

### [D-006] VIC 优先级以 USB PD 为最高，软 WDT 为最低

**原则**: USBPD 中断优先级 = 0（最高），TMR2（软 WDT）= 3（最低）。

**原因**: USB PD BMC 编码的 bit 时序精度要求微秒级，任何中断打断都会导致数据帧破坏和协议失败。软 WDT 的作用是"在所有正常处理都卡住时"才触发复位，它本身不处理实时数据，不需要高优先级。

**推论**: 新增 ISR 时，优先级选择依据是"数据时序精度要求"，而非"业务逻辑重要性"。WPC ASK（ECAP，优先级 2）比 WPC 软件状态机（WPC_TASK 事件，优先级无，协作式）更高，因为 ASK 边沿捕获有硬时序要求。

### [D-007] 软件 I2C 是默认选择，因为可控时序优于性能

**原则**: `hal/i2cm.c` 默认使用 GPIO bit-bang 软件 I2C，而非硬件 I2C 控制器（需 `#ifdef HW_I2CM_` 编译）。

**原因**: 硬件 I2C 在与特定从机设备（SE IC T91206、NU6801/NU6805 等）通信时，ACK 时序的严格性导致部分设备无法正常工作。软件 I2C 的时序完全在固件控制之下，可以针对每种设备的特性调整 SCL 高/低时间。性能损失可接受（I2C 操作主要在 Task 中执行，非实时路径）。

**推论**: 若调试新的 I2C 从机设备失败（HAL 返回 -50 到 -80 错误码），优先检查时序（逻辑分析仪），而不是怀疑软件实现有 bug。如果需要切换到硬件 I2C，需要重新验证所有从机设备的兼容性。

### [D-008] EADC 校准值存储在 Flash，必须在工厂写入，否则测量不准

**原则**: EADC 的 VREF/VCAP 增益和偏置系数从 Flash 地址（0x1C94-0x1CA2）读取。这些值必须在芯片出厂时通过测试写入，否则 FOD 和 Q 因子测量精度显著下降。

**原因**: ADC 参考电压的绝对精度取决于芯片制造工艺，批间差异可达 ±5%。工厂测试时用标准信号校准每颗芯片，将个体校准系数写入片上 Flash，运行时在线补偿。

**推论**: 调试时若 FOD 持续误报，或 Q 因子测量值异常，首先读取 Flash 0x1C94 处的内容，确认校准系数有效（非 0xFF）。替换芯片批次时，新批芯片必须重新进行工厂校准。

## 调试直觉 (Debugging Heuristics)

### [H-001] 系统频繁冷启动，日志中出现 "----powereon reset"

最常见原因: ① 软 WDT（TMR2, 850ms）在某个耗时 Task 处理期间触发，清除 power_on_magic 后复位；② `hal_bsp_init()` 中某个外设初始化耗时 > 850ms 且没有喂狗（常见于 SE IC 证书链读取）。

排查: 在 `soft_wdt_reset()` 入口加日志打印 `sys_ticks`；在 OSAL 主循环加逐次迭代计时，定位哪次迭代 > 850ms；在 BSP 初始化的关键步骤间加 `hal_wdt_feed()`。

### [H-002] USB PD 通信失败或 TypeC 设备频繁断开重连

最常见原因: TMR1 ISR 正常运行但 `usb_pdlib_timer_update()` 调用延迟（某个 Task 占用 CPU > 10ms），导致 USB PD 协议层时基积累误差超出容忍范围。

排查: 检查 OSAL 主循环中有无单次 > 10ms 的事件处理；在 `usb_pdlib_timer_update()` 调用处统计调用间隔，若不稳定则定位 CPU 占用源。

### [H-003] I2C 设备通信成功但数据持续异常，排除了硬件问题

最常见原因: 读取的寄存器是 W1C 语义，但代码用 `reg |= bit` 写操作误清了相邻标志位，下次读时已丢失正确状态。

排查: 对照芯片手册核查寄存器的读写属性；在读操作前后打印原始寄存器值；临时改用 `reg = bit` 写法（只写需要清的 bit）验证。

### [H-004] 添加新 ISR 驱动后，中断始终不触发

最常见原因: ISR 函数名拼写错误（与 `isr.c` 中弱符号名不匹配），链接器不报错，中断仍走弱符号空实现。

排查: 确认函数名与 `isr.c` 中对应的 `__attribute__((isr, weak)) void XXXXX_IRQHandler(void)` 完全一致（大小写敏感）；用 `nm` 或 MAP 文件确认强符号是否覆盖了弱符号；临时在弱符号实现里加打印，确认是否被调用。
