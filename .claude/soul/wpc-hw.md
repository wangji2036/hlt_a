# WPC Hardware 模块经验

## 已确认的模式 (Confirmed Patterns)

### [P-001] PID 是模式选择器，不是传统单变量控制器
- 每个 CEP 只调节四个变量（V/F/D/P）中的一个，按当前工作点选择有余量的那个
- 四变量分别在线性区间内单独调节，避免了 Qi 系统的增益反转问题
- 来源: WPC HW Guide 撰写时 pid.c 完整阅读

### [P-002] VINDPM 在 PID 链路中具有最高优先级，正向 CEP 被屏蔽
- pid_cep_handler() 入口处：if(vindpm_flag && cep > 0) cep = 0
- 协议层的 PCH_TO 事件也独立将 CEP 改为负值（双重保障）
- 来源: Task #5-6 VINDPM 实现 + WPC HW Guide 确认

## 设计意图与不变约束 (Design Rationale & Invariants)

> 这里记录的是「为什么」，不是「是什么」。「是什么」应当读代码。
> 参考完整文档: `docs/WPC_HW_GUIDE.md`

### [D-001] FOD 锁定后的等待时间由 WPC 规范规定，不能缩短

**原则**: PFOD 检测到异物并停止充电后，必须等待约 11 分钟才允许下一次 Ping。这是 WPC 规范强制要求。

**原因**: 金属异物（硬币、钥匙）被 TX 线圈注入能量后温度升高。如果允许立即重试 Ping，在异物未被移走的情况下相当于持续加热，可能引发安全事故。11 分钟冷却时间让异物温度回落到安全范围。

**推论**: 用户反馈"FOD 后等待时间太长"是正常的规范约束行为，不能通过缩短等待时间改善。如需减少用户等待，应通过调整 PFOD 阈值或改进物理模型来减少误报，而不是缩短等待时间。

### [D-002] FSK 发送期间 AFD 必须关闭，ISR 完成后必须重新开启

**原则**: 调用 `fml_fsk_data_send()` 前必须先关闭 AFD（自动频率抖动）；FSK ISR 在最后一个字节发送完成时必须重新开启 AFD。

**原因**: AFD 通过随机微调 EPWM 频率实现 EMI 扩频。FSK 调制依赖精确的频率跳变来编码数据。若两者同时运行，AFD 的随机频率会叠加到 FSK 跳变上，导致 PRx 解调出错误数据，ACK/NAK 丢失或错误接收。

**推论**: 任何在 FSK 发送期间修改 EPWM 频率的操作（包括 AFD、PID 频率调节）都不能进行。FSK ISR 的 AFD 重开逻辑不能删除，否则 AFD 会永久关闭，降低整机 EMI 性能。

### [D-003] NU103X 影子寄存器只能通过 fml_nu103x_config() 更新，不能直接赋值

**原则**: 所有 NU103X 配置更改必须通过 `fml_nu103x_config()` API 进行，该函数先发送硬件脉冲命令，再更新影子寄存器。不能直接修改影子结构体字段。

**原因**: NU103X 使用脉冲计数协议（单根 GPIO），MCU 无法读回其内部状态。影子寄存器是唯一的状态参考。直接赋值影子寄存器不会触发脉冲，硬件状态不变，但代码认为配置已生效。后续的"若当前状态已是目标配置则跳过发送"判断会基于错误的影子状态做出错误决策，实际配置长期不更新。

**推论**: 若 DMO 配置后 ASK 接收仍然失败，首先怀疑影子寄存器同步问题（代码路径中有无直接赋值操作）；其次怀疑 NU103X 脉冲发送时序（GPIO 切换是否完整）。

### [D-004] QDT 阻塞版本只能在 BSP 初始化阶段使用；任务周期中必须用非阻塞状态机

**原则**: `fml_qdt_detect()`（阻塞，约 2ms）只允许在 `osal_start_system()` 之前调用。IDLE 阶段的周期性 QDT 检测必须使用 `fml_qdt_detect_1()`（三状态状态机，非阻塞）。

**原因**: 2ms 的 ECAP 等待对于协作式 OSAL 调度器是不可接受的阻塞。OSAL 主循环每次迭代要为所有 Task 服务，2ms 阻塞会使 TMR1 驱动的 USB PD 时基积累误差（每 10ms 应调用 `usb_pdlib_timer_update()`）。

**推论**: 如果需要新的阻塞式硬件测量（如新 ADC 序列），应评估其耗时：< 100µs 可直接调用，100µs~2ms 需加喂狗考虑，> 2ms 必须拆分为状态机。

### [D-005] PFOD 功率损失计算基于物理模型，icol_rms 必须在 XFER 稳态后才有效

**原则**: PFOD 的 `ploss_calc()` 依赖 ECAP 测量的线圈电流 RMS 值。只有在 EPWM 启动并且 PID 稳定（CEP 在 ±2 范围内）之后，PFOD 的 FOD 计数才能开始累积。

**原因**: EPWM 刚启动时有几个周期的电流建立瞬态，`icol_rms` 测量值偏高。若此时 PFOD 开始计数，即便没有异物也可能因 `Pcoil = 160 × icol_rms²` 过高而误报 FOD。

**推论**: PFOD 的 `pfod_init()` 或使能计数的逻辑，必须在 XFER 稳态确认后调用，而不是 XFER 阶段开始时立即调用。若系统总是在 XFER 开始 1-2 秒内触发 FOD，首先检查 PFOD 计数启动时机。

### [D-006] ASK 双解码器设计是信号容错机制，不是冗余

**原则**: Bit 层维护两套解码参数（Decoder 0 严格，Decoder 1 宽松），同时处理同一段时间戳，哪个先完成有效包校验就使用哪个的结果。

**原因**: 不同手机品牌的 ASK 调制精度差异显著（有些品牌半宽位可能达到 300µs，有些只有 140µs）。单一解码参数无法覆盖所有设备。双解码器让系统在信号质量高时用严格时序（减少误码），在信号较差时自动用宽松时序（提高成功率）。

**推论**: 若某款手机只有宽松解码器能解码成功（Decoder 1 命中，Decoder 0 全部失败），这是正常的容错行为。若两个解码器都失败，说明该手机的 ASK 时序超出了所有已定义范围，需要调整时序参数常量。

### [D-007] DMO 多信道轮转是对通信信道不稳定性的主动适应，不是出错后的被动恢复

**原则**: 在 XFER 阶段，DDM 看门狗定期检查 ASK 接收状态，若超时则主动轮换 DMO 信号源和增益配置，不等到通信完全断开再处理。

**原因**: 无线充电过程中，用户可能微调手机位置，磁场分布随之变化，最优 DMO 信道也会随之变化。被动等待（直到通信断开再重连）会导致充电中断，用户体验差。主动轮换在通信质量刚开始下降时就切换，避免了完全断开。

**推论**: `ddm_param_chose()` 中的轮转参数顺序不是随意的，是基于实验确定的覆盖范围最广的顺序。不能为了简化代码而减少轮转配置数量（会降低对不同手机的兼容性）。

### [D-008] PFOD 阈值分两级是因为异物历史改变了风险评估

**原则**: PFOD 使用两个不同的阈值：当 `tx_infos.fo_exist == 0`（无异物历史）时使用宽松阈值；当 `fo_exist == 1`（曾检测到异物特征）时使用严格阈值。

**原因**: 一旦系统认为某次放置中存在异物，当前充电会话的风险就比从未有过异物的会话高。即便 PRx 现在在位，金属异物可能仍在线圈附近（被手机部分遮住）。用严格阈值继续监测，不能因为 PRx 接入就完全信任当前放置情况。

**推论**: `tx_infos.fo_exist` 标志的设置逻辑不能随便清除（不能在 XFER 开始时重置），否则会导致有异物历史的放置环境用宽松阈值，漏检风险。

## 调试直觉 (Debugging Heuristics)

### [H-001] ASK 反复失败（dm_bad_cnt 持续增加），手机可以正常充其他品牌充电器

最常见原因: ① 手机放置位置偏移，线圈耦合弱，ASK 信号幅度不足；② DMO 增益设置过低（未匹配当前功率档位）；③ 某个 DMO 配置组合对该手机信号特性不匹配。

排查: 打印每次 DDM watchdog 触发时的 `dm_bad_cnt[]` 和当前 DMO 配置索引；用示波器对比 DMO 引脚的信号幅度；尝试固定特定 DMO 配置观察成功率。

### [H-002] FOD 在充电刚开始时立即触发（XFER 开始 1-3 秒内）

最常见原因: PFOD 计数在 EPWM 电流还未稳定时开始，icol_rms 瞬态值过高导致 ploss 虚高；或 PFOD 阈值对当前手机壳厚度过于严格（厚磁铁壳增加 Pfm 项）。

排查: 打印 `icol_rms` 和 `ploss` 的实时值；观察 FOD 触发前 pfo 的变化趋势；检查 PFOD 计数启动时机是否在 XFER 稳定之后。

### [H-003] PID 功率不稳，m_pid_ctrl_mode 频繁在两种模式间切换

最常见原因: 两个调节变量的限制边界设置相距太近，CEP 轻微变化就导致模式切换；或 VINDPM 间歇性触发，使正向 CEP 被屏蔽导致功率不对称调节。

排查: 打印 m_pid_ctrl_mode 序列；对比 pid_perd/pid_volt 与其各自的 lim_hi/lim_mi/lim_lo；检查 vindpm_flag 是否周期性置位。

### [H-004] QDT 检测 Q 因子后报告 q_fact 极小或异常（接近 0）

最常见原因: `vqm_decay_time_cnt < QDT_DECAY_DLY_TIME`（ECAP 未捕获到有效衰减），可能是 NU103X 未成功切换到 QDT 模式，或 LC 谐振电路问题（电容/线圈开路）。

排查: 打印三个 ECAP 原始测量值（vqm_decay_time_cnt, vqm_width_last_cnt, nqm_reson_freq_cnt）；确认 NU103X QDT 初始化命令是否成功执行（通过影子寄存器确认）；测量谐振频率是否在合理范围（约 128kHz 或 360kHz）。
