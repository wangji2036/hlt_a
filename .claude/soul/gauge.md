# Gauge BMS 模块经验

> 参考完整文档: `docs/GAUGE_GUIDE.md`

## 已确认的模式 (Confirmed Patterns)

### [P-001] Simulink 自动生成代码严禁手动修改
- **原则**: `gauge/` 目录下所有 `.c` / `.h` 文件均为 MATLAB Simulink R2024b 自动生成，任何参数调整必须在 `BMS_FixPoint.slx` 模型中完成，然后重新生成代码
- **原因**: Simulink 重新生成代码会完整覆盖整个 `gauge/` 目录，任何手动修改会在下一次代码生成时丢失，且不会有任何提示
- **推论（Implication）**: 如果在 `gauge/` 文件中发现手写注释或局部修改，说明有人违反此规则，这些修改迟早会消失；需要立即提取到 Simulink 模型中才能永久保留

### [P-002] 电流符号约定：正值 = 充电，负值 = 放电
- **原则**: `SigPr_PackCurr_mA_s` 正值表示电流流入电池（充电），负值表示电流流出电池（放电）
- **原因**: BMS 的 Ah 积分方向由符号决定。充电时 SOC 应上升（正积分），放电时 SOC 应下降（负积分）
- **推论**: 如果传入符号相反，充电时 SOC 持续下降，放电时 SOC 持续上升。这是移植到新平台时最常见的配置错误。检查方法：充电时打印该变量，应为正数（如 +2500mA）

### [P-003] 每次上电必须触发一次 OCV 校正
- **原则**: `gd->SOC_SleepTime_s` 在系统初始化时必须设为大于 1800 的值（当前硬编码 2000），确保首次 `Cyclic()` 调用立即触发 OCV 更新，用实时电压校正 NVM 中可能过时的 SOC
- **原因**: 关机后 Ah 积分器停止运行，NVM 保存的 SOC 是上次关机时的值。实际可能已经自放电或温度变化，导致 NVM 值和真实 SOC 有偏差
- **推论**: 如果 `SOC_SleepTime_s` 在上电时被设为 0，则首次上电不触发睡眠松弛校正，需要等空载 25 分钟后 OCV 才能修正，期间显示 SOC 可能与真实值偏差 3-5%

### [P-004] SOCPack 的双侧缓冲：底部 2% + 顶部 6%
- **原则**: 可用 SOC 范围为 `[EmptySOC + 2%, 94%]`，底部留 2% 防止边界抖动，顶部留 6%（94% 对应 100% 显示）
- **原因**: EmptySOC 本身是估算值，±1-2% 误差不可避免；若不留缓冲，SOC 在 EmptySOC 附近会频繁触发 0% 显示和回弹。顶部 94% 是充电保护考量，不希望电池长期保持 100% 电压加速老化
- **推论**: 充满电时 `SOC_RawSOC_mpct` ≈ 94000（不是 100000）。`DisplaySOC = 100%` 是由 BuckBoost 检测到充电完成后外部强制设置 `real_soc_show=100` 实现的，而不是 BMS 算法自然输出 100%

### [P-005] 显示 SOC 滤波非对称：上升 0.1%/周期，下降 1.0%/周期
- **原则**: 充电时显示 SOC 每 100ms 最多上升 0.1%（1%/秒），放电时最多下降 1.0%（10%/秒），下降速率是上升速率的 10 倍
- **原因**: 用户体验与安全的平衡——充电时慢更新防止 ADC 噪声导致 SOC 虚高（虚高会提前停止充电）；放电时快更新确保电量减少时立即反映，防止用户以为还有电
- **推论**: 如果修改为对称滤波或都设为慢速，充电时 ADC 噪声会导致显示跳变；如果都设为快速，短暂的电流波动会在显示上产生可见的抖动

## 已知陷阱 (Known Pitfalls)

### [T-001] 电流符号传入错误导致 SOC 方向反转
- **症状**: 充电时 LED 显示电量持续减少；放电时 LED 显示电量持续增加
- **原因**: `SigPr_PackCurr_mA_s` 被传入了反向值（如充电时传负值）
- **规避**: 移植到新平台时必须验证电流符号。BuckBoost ADC 通常测量的是充电电流（正方向流入电池），但某些 IC 可能输出的是放电为正的约定——需要在接入 BMS 前做符号翻转

### [T-002] SleepTime_s 被误改为 0
- **症状**: 每次上电后 30 分钟内 SOC 显示可能偏差 3-5%，30 分钟后自然修正（OCV 松弛触发）
- **原因**: `gd->SOC_SleepTime_s = 0` 不满足 1800s 门限，不触发上电 OCV 校正
- **规避**: 此值在 `g_data.c` 初始化时硬编码为 2000，**不要修改**。若需要"真实睡眠时长"功能，需要额外的 RTC 计时并在适当时机赋值

### [T-003] NVM SOC 无校验保护
- **症状**: 上电时 SOC 显示异常值（如 0% 或 100%），电量急剧跳变
- **原因**: Flash 中保存的 SOC 数据损坏，无法区分损坏数据和合法值
- **规避**: 写 NVM 时附加校验（如 XOR 校验字）；读 NVM 时验证范围（0-100000 mpct）和校验字；损坏时使用当前电压查 OCV 表估算初始 SOC

### [T-004] 极端温度下查找表边界截断
- **症状**: 在 <0°C 或 >45°C 环境下，SOC 估算精度下降（可能偏差 5-10%），但不会崩溃
- **原因**: OCV 查找表温度轴范围通常为 [0°C, 25°C, 45°C]，边界外使用最近行数据截断，而非线性外推
- **规避**: 在极端温度场景（寒冷地区/高温汽车内）测试时需降低对 SOC 精度的预期；若产品目标温度范围超出 [0°C, 45°C]，需要在 Simulink 模型中补充低温/高温 OCV 测试数据

## 调试经验 (Debugging Lessons)

### [D-001] SOC 长时间不更新的诊断顺序
1. 确认 `Cyclic()` 每 100ms 被调用（在 BUCKBOOST_TASK 中找调用链）
2. 打印 `SigPr_PackCurr_mA_s`：充电时应为正值，空载时应为接近 0 的小值（1-5mA）
3. 检查 `SOC_OCVUpd_flg` 是否曾经变为 true（OCV 更新代表一次归零）
4. 如果从不更新：电流是否持续 >40mA（如持续充电过程中）？这是正常的——OCV 只在低电流松弛时触发

### [D-002] SOC 突变的诊断顺序
1. 检查 `SOC_OCVUpd_flg` 是否在跳变时刻从 false 变 true（OCV 更新导致的轻微校正是正常现象，跳变量 <5% 可接受）
2. 检查上电时 NVM 加载是否异常（打印上电时 `BMS_NvmSOC_mpct`，应在合理范围）
3. 检查是否有温度骤变（`SigPr_CellTemps_C_s` 急剧下降 → EmptySOC 上升 → 可用 SOC 范围收窄 → DisplaySOC 下降）

## 待验证假设 (Unverified Hypotheses)

### [H-001] SOC 区间压缩代码可能是死代码
- **背景**: 在 `SOCPack.c` 中存在 SOC 中段（25%-80%）压缩逻辑，但相关系数 `Add2_c / Add2_c = 1`
- **假设**: 该压缩功能从未被实际激活，代码路径始终输出原始 UsableSOC 而无压缩
- **需要验证**: 在不同 SOC 点测量 `SOCPack_RealSOC_pct` 与 `UsableSOC` 的差值，若始终为零，则确认此假设
