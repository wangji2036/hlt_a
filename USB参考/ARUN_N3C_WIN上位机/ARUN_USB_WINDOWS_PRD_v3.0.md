## 1. 产品概述

### 1.1 产品定位

基于 USB HID 协议的充电宝电池管理系统上位机软件，面向 **新国标 (GB/T 35590)** 合规的充电宝产品，提供：

- **实时监控**: 电量百分比、电芯电压/温度、循环次数实时展示
- **设备信息**: 生产厂家、产品型号、电池参数、安全使用年限
- **异常追溯**: 过温/过压/过流异常事件的历史记录展示
- **工程写入**: 生产日期、循环次数等工程参数的在线写入
- **生产写入**: 产线阶段设备基本信息 (厂家/型号/电芯/日期) 写入 Flash

## 2. 功能需求

### 2.1 F1 — 设备连接管理

#### F1.1 设备发现与枚举

| 项目 | 规格 |
|------|------|
| 筛选条件 | VID + PID + Usage Page |
| 默认 VID | 0xFFFF |
| 默认 PID | 0xFFFF |
| 默认 Usage Page | 0xFF00 |
| Usage ID | 0x01 |

- VID / PID / Usage Page 三项均可自定义输入 (HEX 格式)
- 点击"刷新"按指定参数重新枚举
- 点击"扫描所有设备"弹窗列出系统全部 HID 设备

#### F1.2 连接/断开

- 一键连接 / 断开
- 连接成功后自动启动 1Hz 定时读取，并触发一次 CMD_READ_DEVICE_INFO；之后每 `PROD_INFO_REFRESH_INTERVAL_S` 秒 (默认 3s) 周期性重新读取设备信息
- 断开后停止定时器，清理资源
- 状态栏实时显示: 未连接 / 已连接 / 连接失败 / 已断开

#### F1.3 热插拔处理

- 设备拔出时: 自动停止刷新，状态栏提示"设备已断开"
- 设备插入时: 需用户手动点击"刷新"→"连接" (不自动重连)

### 2.2 F2 — 实时数据采集

#### F2.1 通信机制

| 参数 | 值 |
|------|---|
| 协议 | USB HID (Vendor-defined) |
| Report 长度 | 64 字节 (固定) |
| 读取命令 | CMD_READ_STATUS (0x01) |
| 读取频率 | 1 Hz |
| 读取超时 | 1000 ms |
| 线程模型 | 后台 Daemon 线程读取，主线程 GUI 刷新 |

#### F2.2 协议帧格式

**通用协议头 (9 字节):**

```
偏移  字段    类型      值/说明
───────────────────────────────────────
0-2   SOF     u8[3]     0x05 0xA5 0x5A
3     Ver     u8        0x02
4     Type    u8        0x01=遥测 / 0x02=异常日志 / 0x03=设备信息
5-6   Seq     u16 LE    序列号
7-8   Len     u16 LE    有效载荷长度
```

#### F2.3 Report Type 0x01 — 电池遥测数据

从偏移 9 开始的有效载荷:

| 偏移 | 字段 | 类型 | HID 单位 | 显示 |
|------|------|------|---------|------|
| +0 | SOC | u8 | % | ✅ 大圆环 |
| +1~+4 | Capacity | u32 LE | mAh | 不显示 |
| +5~+6 | TotalVoltage | u16 LE | V×100 | ✅ 电压卡片总电压 |
| +7~+8 | TotalCurrent | s16 LE | A×100 | 不显示 |
| +9~+10 | Power | s16 LE | W×10 | 不显示 |
| +11 | ChargeState | u8 | enum | 不显示 |
| +12~+13 | CycleCount | u16 LE | 次 | ✅ 循环次数 |
| +14~+15 | BatteryTemp | s16 LE | °C×10 | ✅ 电芯温度 (电芯1/2 均取此值) |
| +16~+17 | BoardTemp | s16 LE | °C×10 | 不显示 |
| +18 | CellCount | u8 | 个 | 不显示 (固定 2) |
| +19~+20 | Cell1Voltage | u16 LE | V×100 | ✅ 电芯1电压 |
| +21~+22 | Cell2Voltage | u16 LE | V×100 | ✅ 电芯2电压 |
| +23~+24 | R_internal | u16 LE | mΩ | 不显示 |
| +25~+26 | SOH | u16 LE | pct×100 | 不显示 |
| +27~+28 | ErrOverTempCnt | u16 LE | 次 | 不显示 (用于触发日志刷新) |
| +29~+30 | ErrOverVoltCnt | u16 LE | 次 | 不显示 |
| +31~+32 | ErrOverCurrCnt | u16 LE | 次 | 不显示 |
| +33 | ExceptionLogCnt | u8 | 条 | 不显示 |
| +34 | BrandLen | u8 | 字节 | — |
| +35~+41 | Brand | char[] | ASCII | 不显示 (由 F8 取代) |

> **温度智能识别**: raw < 100 时视为整数 °C 直接使用；raw ≥ 100 时 ÷10 转换为 °C。

#### F2.4 Report Type 0x02 — 异常日志 (v1.3 全量传输)

从偏移 9 开始:

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0 | OffsetPage | u8 | 分页偏移 (0/1/2, 自动循环) |
| +1 | ReturnCount | u8 | 本次返回条数 (0~2) |
| +2+ | ExceptionLog[] | **20B×N** | 异常日志条目 |

**每条异常日志 (20 字节, 与 NU17112 `BatteryExceptionRecord_t` 原生格式完全对齐):**

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0~+1 | Year | u16 LE | 年 |
| +2 | Month | u8 | 月 |
| +3 | Day | u8 | 日 |
| +4 | Hour | u8 | 时 |
| +5 | Minute | u8 | 分 |
| +6 | Second | u8 | 秒 |
| +7 | Reserved | u8 | 对齐字节 (忽略) |
| +8 | error_type | u8 | **0x01**=过压(OV), **0x02**=过温(OT), **0x03**=欠温(UT) |
| +9 | sub_type | u8 | OV: 电芯号(1-N); TEMP: 0=充电状态, 1=放电状态 |
| +10~+11 | data_low | u16 LE | OV: 最高单节电压(mV); TEMP: 最高温度(s16, 0.1°C) |
| +12~+13 | data_high | u16 LE | OV: 总电压(mV); TEMP: 0x0000 |
| +14~+15 | Padding | u16 | 0x0000 (忽略) |
| +16~+19 | record_id | u32 LE | NU17112 内部序号，用于去重 (record_id==0 视为无效) |

> **格式说明**: 每条 20 字节，64B HID 报告每包最多携带 2 条（含 9B 协议头 + 2B 元数据 + 2B CRC = 13B 固定开销，剩余 51B，51÷20=2 条）。

**WB7720 分页传输机制 (v1.3):**

WB7720 维护 `exc_cache[5][20]` 本地缓存，每次组装 Type 0x01 遥测报告时从 `i2c_buff[0x37~0x4D]` 检查新记录，按 `record_id` 去重后追加到缓存（最多 5 条）。

分页策略 (每页最多 2 条, 共 3 页):
```
page 0 (OffsetPage=0): exc_cache[0] + exc_cache[1]
page 1 (OffsetPage=1): exc_cache[2] + exc_cache[3]
page 2 (OffsetPage=2): exc_cache[4]
```

页码自动推进: 0→1→2→0→... 确保 PC 周期性获取全部缓存记录。
无记录时发 ReturnCount=0 的空包。

#### F2.5 通信节奏

```
每秒 1 次 _poll_tick:
  若 poll_counter % PROD_INFO_REFRESH_INTERVAL_S == 0:
    → CMD_READ_DEVICE_INFO (0x02) → 刷新设备信息 (3 包 Type 0x03)
  否则:
    → CMD_READ_STATUS (0x01) → Type 0x01 (遥测) 或 Type 0x02 (异常日志)
```

> **默认 PROD_INFO_REFRESH_INTERVAL_S = 3**: 每 3 秒读一次设备信息，其余秒读遥测/异常日志。
> 遥测/异常日志的类型由 WB7720 round-robin 决定 (每 5 次 CMD 0x01 中第 5 次返回 Type 0x02)。

### 2.4 F4 — 异常日志管理

#### F4.1 日志收集策略

- 每 5 次 CMD_READ_STATUS 请求中第 5 次触发 Type 0x02 异常日志回复
- WB7720 按 OffsetPage 分 3 页 (0→1→2→0→...) 循环返回 exc_cache 中的记录
- 上位机按 `record_id` 去重，累积收到的条目追加展示
- `record_id == 0` 视为无效记录，跳过不显示
- **断开连接时清除**: 清空 `_exception_seen_ids` 和 `_exception_list`，因为 WB7720 掉电后 exc_cache 重置，重连后 record_id 可能从头开始

#### F4.2 日志显示格式

文字列表形式，最多显示最新 20 条，超出时向上滚动。

格式: `[#{record_id}] {前缀} {类型描述} {数值单位}[ {时间戳} ]`

- 去重依据: `record_id` (相同 record_id 不重复追加，record_id==0 跳过)
- 同 record_id 记录更新策略: OV 类比较 data_low (最高电压)，OT/UT 类比较 |data_low| (温度绝对值)，保留更严重值
- 排序: 按接收顺序显示 (WB7720 按 OffsetPage 分页返回)

示例:
```
[#1] 电芯1 电池充电电压异常 4.50V (总8.90V)[ 2026-01-08 18:43:23 ]
[#2] 电芯0 电池充电温度异常 55.2℃[ 2026-01-08 18:47:12 ]
[#3] 电芯1 电池放电温度异常 -5.3℃[ 2026-01-09 11:36:12 ]
```

### 2.5 F5 — 工程模式

#### F5.1 模式切换

| 项目 | 值 |
|------|---|
| 入口 | 顶栏 "工程" Toggle |
| 密码 | `123456` |
| 解锁方式 | 弹窗输入密码验证通过后显示面板 |
| 互斥 | 开启时自动关闭生产模式 |

#### F5.2 可写寄存器与写入序列

**密码解锁时立即激活 (全 sentinel 初始化):**

密码验证通过后，上位机立即发送 0xA5 + 全 sentinel 值，激活 NU17112 工程模式但不覆盖任何参数:

```
步骤1: [0x00][0x0C][0x50][0x01][0xA5][填充]                      解锁
步骤2: [0x00][0x0C][0x60][0x07][0x00][0x00][0][0][0][0][0][填充]  当前日期 sentinel (全零=不覆盖 RTC)
步骤3: [0x00][0x0C][0x70][0x04][0x00][0x00][0][0][填充]          生产日期 sentinel (全零=不覆盖)
步骤4: [0x00][0x0C][0x80][0x02][0xFF][0xFF][填充]                循环次数 sentinel (0xFFFF=不覆盖)
步骤5: [0x00][0x0C][0x82][0x02][0xFF][0xFF][填充]                Cell1电压 sentinel (0xFFFF=不覆盖)
步骤6: [0x00][0x0C][0x84][0x02][0xFF][0xFF][填充]                Cell2电压 sentinel (0xFFFF=不覆盖)
步骤7: [0x00][0x0C][0x86][0x02][0xFF][0x7F][填充]                虚拟温度 sentinel (0x7FFF=不覆盖, signed)
```

**用户点击"写入设备"时的写入序列 (每步间隔 50ms):**

每个参数由 checkbox 控制: 勾选且输入非空发用户值，否则发 sentinel (不覆盖设备当前值)。

```
步骤1: [0x00][0x0C][0x60][0x07][年Lo][年Hi][月][日][时][分][秒][填充]  当前日期 (7字节, H/M/S 取发送瞬间)
       或 [0x00][0x0C][0x60][0x07][全零][填充]                        未勾选: sentinel
步骤2: [0x00][0x0C][0x70][0x04][年Lo][年Hi][月][日][填充]              生产日期 (4字节, 仅Y/M/D)
       或 [0x00][0x0C][0x70][0x04][全零][填充]                        未勾选: sentinel
步骤3: [0x00][0x0C][0x80][0x02][次Lo][次Hi][填充]                     循环次数
       或 [0x00][0x0C][0x80][0x02][0xFF][0xFF][填充]                  未勾选: sentinel (0xFFFF)
步骤4: [0x00][0x0C][0x82][0x02][mV_Lo][mV_Hi][填充]                  Cell1电压 (mV)
       或 [0x00][0x0C][0x82][0x02][0xFF][0xFF][填充]                  未勾选: sentinel (0xFFFF)
步骤5: [0x00][0x0C][0x84][0x02][mV_Lo][mV_Hi][填充]                  Cell2电压 (mV)
       或 [0x00][0x0C][0x84][0x02][0xFF][0xFF][填充]                  未勾选: sentinel (0xFFFF)
步骤6: [0x00][0x0C][0x86][0x02][t_Lo][t_Hi][填充]                    虚拟温度 (s16, 0.1°C)
       或 [0x00][0x0C][0x86][0x02][0xFF][0x7F][填充]                  未勾选: sentinel (0x7FFF)
步骤7: [0x00][0x0C][0x88][0x01][0xAA][填充]                          刷新命令: 触发 NU17112 重新应用参数
```

> **Sentinel 机制**: 0xFFFF 表示 Cell1/Cell2 电压和循环次数不覆盖; 0x7FFF (s16) 表示温度不覆盖。
> NU17112 收到 sentinel 值时保持设备当前值不变。

> **0xAA 刷新命令**: 写入 0x88=0xAA 后，NU17112 重新应用全部虚拟参数 (含本次修改的和之前保持的 sentinel 值)，
> 无需退出再进入工程模式。可多次点击"写入设备"反复调整参数。

**清除全部异常记录:**

```
[0x00][0x0C][0x88][0x01][0xEE][填充]    清除命令
```

- 发送后上位机清空本地异常缓存，并进入"等待硬件确认"状态
- 硬件确认方式: WB7720 返回 ReturnCount=0 的空 Type 0x02 报告
- 超时保护: 15 秒内未收到确认则放弃 (`_erase_pending` 超时)
- 用户需通过确认对话框 ("此操作不可恢复") 才可执行

**退出工程模式:**

```
[0x00][0x0C][0x50][0x01][0x00][填充]    退出 (切回用户模式时自动发送)
```

每个字段前有 checkbox (默认勾选)，未勾选或输入为空的字段发送 sentinel (不覆盖设备值)。

```
┌── 工程模式面板 ─────────────────────────────────────────────┐
│  [x] 当前日期(YYYY/MM/DD): [2026/03/03]                     │
│  [x] 生产日期(YYYY/MM/DD): [________]                        │
│  [x] 循环次数(0-65535):    [0]                               │
```

### 2.8 F8 — 设备基本信息读取

#### F8.1 触发时机

上位机成功连接后，**立即发送一次** CMD_READ_DEVICE_INFO (0x02)，读取并缓存设备信息。

之后按 `PROD_INFO_REFRESH_INTERVAL_S` (默认 **3 秒**) 周期性重新读取。每次重读前重置 `DeviceInfo` 缓存，收齐 3 包后更新 UI。此定期刷新确保生产模式写入后 UI 能自动反映最新值。

> 设为 0 可禁用定期刷新，仅连接时读取一次。

#### F8.2 请求格式

```
[0x00][0x02][0x00 × 63]   (hidapi 前缀 0x00, 实际发 65 字节)
```

#### F8.3 响应格式 — Type 0x03 (设备信息)

WB7720 分 **3 包** 返回，每包通用头 Type=0x03, Len=41:

| 包序 | SubIdx (+0) | 字段1 (+1~+20, 20B) | 字段2 (+21~+40, 20B) |
|------|------------|---------------------|---------------------|
| 包1 | 0x00 | manufacturer_name | model_name |
| 包2 | 0x01 | battery_mfr | battery_model |
| 包3 | 0x02 | battery_prod_date | (填充 0x00) |

上位机收到 SubIdx 0x00/0x01/0x02 后组装完整设备信息，显示于卡片4。

> **SubIdx 作为同步标志**: 上位机收到 SubIdx=0x00 时重置缓冲，收到 0x01/0x02 时追加；
> 全部 3 包到齐后更新 UI。若 5 秒内未收齐，卡片4显示 "设备信息读取中..."。

#### F8.4 WB7720 实现要求

- NU17112 每次开机后将已存储的 ProductInfo 写入 i2c_buff 设备信息区
- WB7720 收到 CMD_READ_DEVICE_INFO 后，连续回复 3 包 Type 0x03
- 若 i2c_buff 中信息全为 0xFF (未写入)，返回空字符串

## 3. 命令汇总

| 命令码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x01 | CMD_READ_STATUS | Host→Device | 请求遥测(Type 0x01) 或日志(Type 0x02) |
| 0x02 | CMD_READ_DEVICE_INFO | Host→Device | 请求设备信息 (Type 0x03, 3包) |
| 0x0C | CMD_WRITE_REGISTER | Host→Device | 写工程/生产模式寄存器 |

**发送格式:**
```
[0x00 Report ID] + [CMD] + [payload] + [0x00 填充至 64B]
```
> `0x00` 前缀为 hidapi 无 Report ID 设备要求，实际发 65 字节。

**CMD_WRITE_REGISTER 地址汇总:**

| 地址 | 名称 | 长度 | 模式 | 说明 |
|------|------|------|------|------|
| 0x50 | REG_WORK_MODE | 1B | 工程 | 0xA5=解锁, 0x00=退出 |
| 0x60~0x66 | REG_ENG_CURRENT_DATE | 7B | 工程 | Year(u16 LE)+Month+Day+Hour+Min+Sec; 全零=sentinel |
| 0x70~0x73 | REG_ENG_PRODUCTION_DATE | 4B | 工程 | Year(u16 LE)+Month+Day; 全零=sentinel |
| 0x80~0x81 | REG_ENG_CYCLE_CHG_COUNT | 2B | 工程 | u16 LE 循环次数; 0xFFFF=sentinel |
| 0x82~0x83 | REG_ENG_VIRTUAL_CELL1 | 2B | 工程 | u16 LE Cell1电压 mV; 0xFFFF=sentinel |
| 0x84~0x85 | REG_ENG_VIRTUAL_CELL2 | 2B | 工程 | u16 LE Cell2电压 mV; 0xFFFF=sentinel |
| 0x86~0x87 | REG_ENG_VIRTUAL_TEMP | 2B | 工程 | s16 LE 温度 0.1°C; 0x7FFF=sentinel |
| 0x88 | REG_ENG_ERASE_ALL_CMD | 1B | 工程 | 0xEE=清除全部记录, 0xAA=刷新参数 |
| 0x89 | REG_ENG_CMD_STATUS | 1B | 工程 | 读回: 0x02=成功 |
| 0x90 | PROD_MODE_FLAG | 1B | 生产 | 0xB5=触发写入 |
| 0x92~0xA5 | ProductInfo: manufacturer_name | 20B | 生产 | UTF-8 + 0x00 填充 |
| 0xA6~0xB9 | ProductInfo: model_name | 20B | 生产 | UTF-8 + 0x00 填充 |
| 0xBA~0xCD | ProductInfo: battery_mfr | 20B | 生产 | UTF-8 + 0x00 填充 |
| 0xCE~0xE1 | ProductInfo: battery_model | 20B | 生产 | UTF-8 + 0x00 填充 |
| 0xE2~0xF5 | ProductInfo: battery_prod_date | 20B | 生产 | UTF-8 + 0x00 填充 |

### 5.3 线程模型

```
主线程 (GUI)
  ├── root.after(1000) → 后台线程读取遥测
  └── 连接时 → 后台线程读取设备信息 (CMD 0x02 × 3包)

后台线程
  ├── _read_data_worker(): 发 0x01, 收 Type 0x01/0x02, 回调主线程更新
  ├── _read_device_info_worker(): 发 0x02, 收 3包 Type 0x03, 回调更新设备信息卡
  ├── _enter_eng_on_device(): 密码解锁时发 0xA5 + 全 sentinel, reading_busy=True
  ├── _exit_eng_on_device(): 退出工程模式时发 0x50=0x00
  ├── _write_engineering_worker(): 7步写入 (含 checkbox 判断 + 0xAA 刷新), reading_busy=True
  ├── _erase_worker(): 发 0xEE 清除 + 等待硬件确认, reading_busy=True
  └── _write_production_worker(): 6步写入 + 轮询确认, reading_busy=True

线程安全规则:
1. GUI 更新只在主线程 (root.after())
2. HID 读写不并发 (reading_busy 互斥)
3. CMD_READ_DEVICE_INFO 期间不发 CMD_READ_STATUS
```

## 6. 错误处理
