## 1. 产品概述

### 1.1 产品定位

基于 USB HID 协议的充电宝电池管理系统上位机软件，面向 **新国标 (GB/T 35590)** 合规的充电宝产品，提供：

- **实时监控**: 电量百分比、电芯电压/温度、循环次数实时展示
- **设备信息**: 生产厂家、产品型号、电池参数、安全使用年限
- **异常追溯**: 过温/过压/过流异常事件的历史记录展示
- **工程写入**: 生产日期、循环次数等工程参数的在线写入
- **生产写入**: 产线阶段设备基本信息 (厂家/型号/电芯/日期) 写入 Flash

### 1.4 系统上下文

```
Windows PC
  └── ARUN 充电宝智能监测系统 (本 PRD)
       ├── tkinter GUI (5卡片布局)
       ├── HID 通信 (1Hz 轮询)
       │    ├── CMD_READ_STATUS (0x01) → 实时遥测 + 异常日志
       │    └── CMD_READ_DEVICE_INFO (0x02) → 设备基本信息

  └── I2C Slave @0x42, i2c_buff[256]
         ↕ I2C Bus
NU17112 + NU6805 主控 (2S Li-ion)
```

## 2. 功能需求

### 2.1 F1 — 设备连接管理

#### F1.1 设备发现与枚举

| 项目 | 规格 |
|------|------|
| 筛选条件 | VID + PID + Usage Page |
| 默认 VID | 0xFFFF |
| 默认 PID | 0xFFFF |
| 默认 Usage Page | 0xFF00 |
| Usage ID | 0x01 |

- VID / PID / Usage Page 三项均可自定义输入 (HEX 格式)
- 点击"刷新"按指定参数重新枚举
- 点击"扫描所有设备"弹窗列出系统全部 HID 设备

#### F1.2 连接/断开

- 一键连接 / 断开
- 连接成功后自动启动 1Hz 定时读取，并触发一次 CMD_READ_DEVICE_INFO
- 断开后停止定时器，清理资源
- 状态栏实时显示: 未连接 / 已连接 / 连接失败 / 已断开

#### F1.3 热插拔处理

- 设备拔出时: 自动停止刷新，状态栏提示"设备已断开"
- 设备插入时: 需用户手动点击"刷新"→"连接" (不自动重连)

### 2.2 F2 — 实时数据采集

#### F2.1 通信机制

| 参数 | 值 |
|------|---|
| 协议 | USB HID (Vendor-defined) |
| Report 长度 | 64 字节 (固定) |
| 读取命令 | CMD_READ_STATUS (0x01) |
| 读取频率 | 1 Hz |
| 读取超时 | 1000 ms |
| 线程模型 | 后台 Daemon 线程读取，主线程 GUI 刷新 |

#### F2.2 协议帧格式

**通用协议头 (9 字节):**

```
偏移  字段    类型      值/说明
───────────────────────────────────────
0-2   SOF     u8[3]     0x05 0xA5 0x5A
3     Ver     u8        0x02
4     Type    u8        0x01=遥测 / 0x02=异常日志 / 0x04=设备信息
5-6   Seq     u16 LE    序列号
7-8   Len     u16 LE    有效载荷长度
```

#### F2.3 Report Type 0x01 — 电池遥测数据

从偏移 9 开始的有效载荷:

| 偏移 | 字段 | 类型 | HID 单位 | 显示 |
|------|------|------|---------|------|
| +0 | SOC | u8 | % | ✅ 大圆环 |
| +1~+4 | Capacity | u32 LE | mAh | 不显示 |
| +5~+6 | TotalVoltage | u16 LE | V×100 | ✅ 电压卡片总电压 |
| +7~+8 | TotalCurrent | s16 LE | A×100 | 不显示 |
| +9~+10 | Power | s16 LE | W×10 | 不显示 |
| +11 | ChargeState | u8 | enum | 不显示 |
| +12~+13 | CycleCount | u16 LE | 次 | ✅ 循环次数 |
| +14~+15 | BatteryTemp | s16 LE | °C×10 | ✅ 电芯温度 (电芯1/2 均取此值) |
| +16~+17 | BoardTemp | s16 LE | °C×10 | 不显示 |
| +18 | CellCount | u8 | 个 | 不显示 (固定 2) |
| +19~+20 | Cell1Voltage | u16 LE | V×100 | ✅ 电芯1电压 |
| +21~+22 | Cell2Voltage | u16 LE | V×100 | ✅ 电芯2电压 |
| +23~+24 | R_internal | u16 LE | mΩ | 不显示 |
| +25~+26 | SOH | u16 LE | pct×100 | 不显示 |
| +27~+28 | ErrOverTempCnt | u16 LE | 次 | 不显示 (用于触发日志刷新) |
| +29~+30 | ErrOverVoltCnt | u16 LE | 次 | 不显示 |
| +31~+32 | ErrOverCurrCnt | u16 LE | 次 | 不显示 |
| +33 | ExceptionLogCnt | u8 | 条 | 不显示 |
| +34 | BrandLen | u8 | 字节 | — |
| +35~+41 | Brand | char[] | ASCII | 不显示 (由 F8 取代) |

> **温度智能识别**: raw < 100 时视为整数 °C 直接使用；raw ≥ 100 时 ÷10 转换为 °C。

#### F2.4 Report Type 0x02 — 异常日志

从偏移 9 开始:

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0 | OffsetPage | u8 | 分页偏移 |
| +1 | ReturnCount | u8 | 本次返回条数 (0-2) |
| +2+ | ExceptionLog[] | **20B×N** | 异常日志条目 |

**每条异常日志 (20 字节, 与 NU17112 `BatteryExceptionRecord_t` 原生格式完全对齐):**

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0~+1 | Year | u16 LE | 年 |
| +2 | Month | u8 | 月 |
| +3 | Day | u8 | 日 |
| +4 | Hour | u8 | 时 |
| +5 | Minute | u8 | 分 |
| +6 | Second | u8 | 秒 |
| +7 | Reserved | u8 | 对齐字节 (忽略) |
| +8 | error_type | u8 | **0x01**=过压(OV), **0x02**=过温(OT), **0x03**=欠温(UT) |
| +9 | sub_type | u8 | OV: 电芯号(1-N); TEMP: 0=充电状态, 1=放电状态 |
| +10~+11 | data_low | u16 LE | OV: 最高单节电压(mV); TEMP: 最高温度(s16, 0.1°C) |
| +12~+13 | data_high | u16 LE | OV: 总电压(mV); TEMP: 0x0000 |
| +14~+15 | Padding | u16 | 0x0000 (忽略) |
| +16~+19 | record_id | u32 LE | NU17112 内部序号，用于去重和排序 |

> **格式说明**: 每条 20 字节，64B HID 报告每包最多携带 2 条（含 9B 协议头 + 2B 元数据 + 2B CRC = 13B 固定开销，剩余 51B，51÷20=2 条）。
> 分页获取: PC 发 CMD_READ_STATUS(0x01) 第 5 次时触发，WB7720 通过 OffsetPage 分页返回所有记录。

#### F2.5 通信节奏

```
请求 1~4 → Type 0x01 (遥测) → 刷新电量/温度/电压/循环次数
请求 5   → Type 0x02 (异常日志) → 刷新异常监督记录
...循环
```

### 2.4 F4 — 异常日志管理

#### F4.1 日志收集策略

- 每 5 次请求中的第 5 次自动获取异常日志 (Type 0x02)
- 上位机累积收到的条目，去重后展示 (以时间戳为主键)
- 支持分页 (OffsetPage)，逐步获取全部历史日志

#### F4.2 日志显示格式

文字列表形式，最多显示最新 20 条，超出时向上滚动。

格式: `{前缀+类型描述} {数值单位}[ {时间戳} ]`

- 去重依据: `record_id` (相同 record_id 不重复追加)
- 排序: 按接收顺序显示 (WB7720 按 OffsetPage 分页返回)

示例:
```
电芯1 电压过高 4.50V (总8.90V)[ 2026-01-08 18:43:23 ]
充电 过温 55.2℃[ 2026-01-08 18:47:12 ]
放电 欠温 -5.3℃[ 2026-01-09 11:36:12 ]
```

### 2.6 F6 — 生产模式

#### F6.1 模式概述

产线阶段向充电宝写入设备基本信息 (ProductInfo → Flash 0x1800)。

| 项目 | 值 |
|------|---|
| 入口 | 顶栏 "生产" Toggle |
| 密码 | `123456` |
| 互斥 | 开启时自动关闭工程模式 |

#### F6.2 写入字段

| 字段 | UI 标签 | 固件字段 | 最大长度 |
|------|--------|---------|---------|
| 充电宝厂家 | 生产厂家 | `manufacturer_name` | 19 字符 |
| 产品型号 | 产品型号 | `model_name` | 19 字符 |
| 电芯厂商 | 电池生产厂商 | `battery_mfr` | 19 字符 |
| 电芯型号 | 电池型号 | `battery_model` | 19 字符 |
| 生产日期/代码 | 代码/生产日期 | `battery_prod_date` | 19 字符 |

#### F6.3 写入序列 (7步, 每步间隔 50ms)

```
步骤1: [0x0C][0x90][0x01][0xB5]          解锁生产模式
步骤2: [0x0C][0x92][0x14][20B 厂家]      写厂家名称
步骤3: [0x0C][0xA6][0x14][20B 型号]      写产品型号
步骤4: [0x0C][0xBA][0x14][20B 电芯厂]    写电芯厂商
步骤5: [0x0C][0xCE][0x14][20B 电芯型]    写电芯型号
步骤6: [0x0C][0xE2][0x14][20B 日期]      写生产日期
步骤7: 轮询 PROD_WRITE_STATUS (每200ms, 超时5s)
  → 0x02 = 写入成功, 0xFF = 写入失败
```

#### F6.4 面板布局

```
┌── 生产模式面板 ─────────────────────────────────────────┐
│  生产厂家:  [________________]   产品型号:  [__________] │
│  电池生产厂商:[_______________]  电池型号:  [__________] │
│  代码/生产日期:[______________]                          │
│                               [写入设备]  状态: ● 就绪  │
└────────────────────────────────────────────────────────┘
```

**状态指示**: 就绪(灰) → 写入中(金色旋转) → 等待确认(蓝色旋转) → 成功(绿) / 失败(红)

### 2.8 F8 — 设备基本信息读取

#### F8.1 触发时机

上位机成功连接后，**立即发送一次** CMD_READ_DEVICE_INFO (0x02)，读取并缓存设备信息。

#### F8.2 请求格式

```
[0x00][0x02][0x00 × 63]   (hidapi 前缀 0x00, 实际发 65 字节)
```

#### F8.3 响应格式 — Type 0x04 (设备信息)

WB7720 分 **3 包** 返回，每包通用头 Type=0x04, Len=41:

| 包序 | SubIdx (+0) | 字段1 (+1~+20, 20B) | 字段2 (+21~+40, 20B) |
|------|------------|---------------------|---------------------|
| 包1 | 0x00 | manufacturer_name | model_name |
| 包2 | 0x01 | battery_mfr | battery_model |
| 包3 | 0x02 | battery_prod_date | (填充 0x00) |

上位机收到 SubIdx 0x00/0x01/0x02 后组装完整设备信息，显示于卡片4。

> **SubIdx 作为同步标志**: 上位机收到 SubIdx=0x00 时重置缓冲，收到 0x01/0x02 时追加；
> 全部 3 包到齐后更新 UI。若 5 秒内未收齐，卡片4显示 "设备信息读取中..."。

#### F8.4 WB7720 实现要求

- NU17112 每次开机后将已存储的 ProductInfo 写入 i2c_buff 设备信息区
- WB7720 收到 CMD_READ_DEVICE_INFO 后，连续回复 3 包 Type 0x04
- 若 i2c_buff 中信息全为 0xFF (未写入)，返回空字符串

## 3. 命令汇总

| 命令码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| 0x01 | CMD_READ_STATUS | Host→Device | 请求遥测(Type 0x01) 或日志(Type 0x02) |
| 0x02 | CMD_READ_DEVICE_INFO | Host→Device | 请求设备信息 (Type 0x04, 3包) |
| 0x0C | CMD_WRITE_REGISTER | Host→Device | 写工程/生产模式寄存器 |

**发送格式:**
```
[0x00 Report ID] + [CMD] + [payload] + [0x00 填充至 64B]
```
> `0x00` 前缀为 hidapi 无 Report ID 设备要求，实际发 65 字节。

**CMD_WRITE_REGISTER 地址汇总:**

| 地址 | 名称 | 模式 |
|------|------|------|
| 0x50 | REG_WORK_MODE (0xA5=解锁) | 工程 |
| 0x60~0x63 | REG_ENG_CURRENT_DATE | 工程 |
| 0x70~0x73 | REG_ENG_PRODUCTION_DATE | 工程 |
| 0x80~0x81 | REG_ENG_CYCLE_CHG_COUNT | 工程 |
| 0x90 | PROD_MODE_FLAG (0xB5=解锁) | 生产 |
| 0x92~0xF5 | ProductInfo 5字段 (各20B) | 生产 |

### 5.2 数据结构

```python
@dataclass
class BatteryData:
    # 显示字段
    soc: int = 0                    # 电量 (%)
    cycle_count: int = 0            # 循环次数
    bat_temp: float = 0.0           # 电芯温度 (°C)
    total_voltage: float = 0.0      # 总电压 (V)
    cell1_voltage: float = 0.0      # 电芯1电压 (V)
    cell2_voltage: float = 0.0      # 电芯2电压 (V)
    voltage_delta: float = 0.0      # 电压差 (V), 计算值
    exception_logs: List[Dict] = [] # 异常日志列表

    # 内部字段 (不显示, 用于调试和判断)
    capacity: int = 0
    current: int = 0
    power: float = 0.0
    board_temp: float = 0.0
    r_internal: int = 0
    soh: int = 0
    charge_state: int = 0

@dataclass
class DeviceInfo:
    manufacturer: str = ""          # 生产厂家
    model: str = ""                 # 产品型号
    battery_mfr: str = ""           # 电池生产厂商
    battery_model: str = ""         # 电池型号
    prod_date: str = ""             # 代码/生产日期
    safety_years: str = "5年"       # 安全使用年限 (硬编码)
    loaded: bool = False            # 是否已读取完整
```

### 5.3 线程模型

```
主线程 (GUI)
  ├── root.after(1000) → 后台线程读取遥测
  └── 连接时 → 后台线程读取设备信息 (CMD 0x02 × 3包)

后台线程
  ├── _read_data_worker(): 发 0x01, 收 Type 0x01/0x02, 回调主线程更新
  ├── _read_device_info(): 发 0x02, 收 3包 Type 0x04, 回调更新设备信息卡
  ├── _write_engineering_data(): 4步写入, reading_busy=True
  └── _write_product_info(): 7步写入 + 轮询, reading_busy=True

线程安全规则:
1. GUI 更新只在主线程 (root.after())
2. HID 读写不并发 (reading_busy 互斥)
3. CMD_READ_DEVICE_INFO 期间不发 CMD_READ_STATUS
```

## 6. 错误处理

| 场景 | 处理 |
|------|------|
| 设备信息读取超时 (5s) | 卡片4 显示 "设备信息读取超时，请重新连接" |
| 遥测读取超时 | 保持上次数据，不清空 UI |
| 协议头校验失败 | 跳过，打印 warning |
| 设备断开 | 停止刷新，清空所有卡片数据 |
| 工程/生产写入失败 | 弹窗提示 + 状态栏显示失败原因 |

## 8. 已知限制

| 限制 | 说明 |
|------|------|
| 电芯温度仅1路NTC | 电芯1/2 显示相同温度 |

| 设备信息需固件支持 | CMD_READ_DEVICE_INFO 需 WB7720 固件实现 F8 规格 |
| 单设备连接 | 同时只能连接 1 个设备 |
| 无数据持久化 | 关闭程序后数据丢失 |
